# `knowledge/transmission/proposed/` — auto-proposed chains (TXI-W5 Loop C)

This directory holds transmission chains **proposed (semi-)autonomously** through the Causal
Hypothesis Factory (CHF) brainstorm lane and materialized by
`scripts/ingest_transmission_chains.py`. It is deliberately **separate** from the top-level
`knowledge/transmission/` seeds so that autonomous proposals **never silently mix** with
human-reviewed chains until a human promotes them.

## What a `proposed/` chain is — and is NOT

A chain in this directory is:

- **`tier: hypothesis`, `source: chf_proposal`, `rev: 0`** — stamped by the ingest, not by
  the LLM. Its per-hop conditional base rates are untested; it prints "untested".
- **auto-compiled by W1** — `engine.transmission_chains.load_chains` globs this subdir, so the
  nightly compiler tracks the proposed chain's episode state (dormant → arming → …) exactly
  like a seed. It is tagged `_proposed: true` in memory.
- **auto-backtested by W3** — `engine.transmission_calibration` loads the same set, so the
  weekly episode miner mines its historical hop base rates on the next cycle.

A chain in this directory is **NOT**:

- **armed on any signal surface.** It is **display/context tier only**. It never emits an
  alpha score, gate, size, rank, or escalation (DNR row 45 / TXI Article 1/2). The ingest
  rejects any proposal carrying an authority field.
- **promoted.** Promotion to authority (and to the top-level library) is **human-only** and
  gauntlet-gated (TXI-R5). The LLM proposes; it never grants authority (CHF-R17: LLMs
  de-escalate only).

## Lifecycle (Loop C)

```
CHF surprise_queue  ┐
metabolism lessons  ┼─▶ propose_transmission_chains.py  ─▶  PACK  ─▶  CHF brainstorm lane (LLM)
existing library    ┘        (deterministic, no LLM)                   (generator→skeptic→…)
                                                                              │
                                                                     chain-shaped replies
                                                                              ▼
   knowledge/transmission/proposed/<slug>.yaml  ◀── ingest_transmission_chains.py
   (hypothesis-tier, display-only)                   (validate + resolve nodes + dedup;
             │                                        unresolvable/malformed → rejected to
             │  W1 compiles state + W3 backtests      data/transmission/proposal_rejects.jsonl)
             ▼
   HUMAN PR review + promotion  ──▶  moves the file OUT of proposed/ (→ top-level library),
                                     the ONLY step that lets a chain earn authority (gauntlet).
```

## Autonomy is operator-gated (default OFF)

The proposal → ingest cycle (`scripts/run_transmission_proposals.py`, weekly) runs **only**
when **both** gates are on:

| gate | file | ships |
|---|---|---|
| CHF autonomy (existing, CHF-R8) | `config/causal_llm.yml` → `auto_loop` | operator-flipped |
| this lane's sub-flag | `config/transmission_proposals.yml` → `enabled` | **`false`** |

Wiring the lane into `weekly.yml` cannot auto-activate it: with `enabled: false` the runner
no-ops (writes nothing, exit 0). An operator flips `enabled: true` in a one-line PR when
ready. This lane builds **no second LLM loop** — the LLM proposing happens inside the CHF
brainstorm lane it rides.

## For a human reviewer

To **promote** a proposed chain: review the YAML (nodes resolve, hops/mechanism sound,
falsifiers + null model present), then in a PR `git mv` it to `knowledge/transmission/` and
bump `rev` with a changelog line. To **reject** it: delete the file (a kill worth recording
goes to `knowledge/transmission/killed/` per TXI-R10). Do **not** hand-edit chains in place
here — they are regenerated by the ingest.
