# Binding routing correction

The F04 parent remains active and logically owned by the existing COO/F04 responsibility. Provider
sessions are execution resources, not organizational identities. A Fable provider conversation is
therefore not required merely to start a child whose architecture and acceptance boundary are already
fully frozen.

## D2C / D2D release and placement rule

After this routing correction is main-canonical, Sol performs a fresh current-state/path collision
census for the existing D2C and D2D operation identities. D2C remains first by default. D2D may be
eligible in parallel only when its actual planned modifying paths are proven disjoint from D2C.

For each child:

- `PREFERRED_AVENUE: Terra` unless fresh mission evidence justifies escalation;
- the avenue label is capability preference only and never a concrete account/session binding;
- preserve the existing stable operation key and logical F04 responsibility;
- if no lawful RuntimeBinding/receiver exists and current automatic placement is not production-proven,
  record `PARKED / WAITING_CAPACITY`, `needs_placement=true`, `turn_owner=EXECUTIVE_PLACEMENT`;
- do not create a broad `OPEN_PICKUP` broadcast or child-specific continuation watcher while no lawful
  receiver/communication path exists merely to make the program look active;
- consume a bounded manual receiver binding only when it is independently supplied by a current lawful
  directive/path; do not ask the Chairman to act as routine quota allocator;
- once a lawful receiver exists, preserve the current pickup/read/communication/START discipline and
  post-START RuntimeBinding stickiness; terminal child STOP authorizes no successor.

The current protected organizational-continuity amendment is `SPEC_ONLY`; it does not itself establish
that automatic placement is live. The separate CF2-H0 transport is now source-released but remains
`BUILT_NOT_PROVEN / PRODUCTION_INERT`, so neither source state can be used as a receiver, RuntimeBinding,
ACK, START or watcher receipt.

## Fable escalation rule

Escalate a child to Fable only when current evidence establishes a principal-level condition such as:

- unresolved cross-owner architecture/authority collision;
- inability to freeze a safe source/identity/rights boundary;
- sustained multi-repository integration ambiguity that bounded workers cannot resolve;
- stalled-program recovery after effect/state reconciliation.

Routine implementation, tests, CI repair, current-source archaeology and bounded independent review
remain worker labor and should not consume Fable by default.

## Unchanged architecture

This ruling changes no GMI graph identity, event/source/identity owner, ThemeState authority, K3-D
boundary, TXI/incorporation/dislocation ownership, Prophet/Entry authority or MarketOntology parity
scope. The finish-and-fold sequence remains:

`D2C + D2D -> D2E -> W3B -> W3C -> GMI development close`

No standalone GMI W4/W5/W6 is restored. No MarketOntology-specific worker router, placement ledger,
watcher control plane or second RuntimeBinding registry is created.
