# Binding execution ruling

This DEC amends the **scope and operating model** of the 2026-08-23 Market
Intelligence Productization masterplan without changing its one-canonical-system
architecture. Where the earlier plan or authenticated adjudication says a useful
Market Ontology capability is merely "held", "later", or outside immediate impact,
that language now means **sequenced later**, not excluded from the parity program.

## Program completion gate

Market Ontology productization may not be declared complete until:

1. all 88 authenticated paid capability rows have exactly one disposition from
   `PROVEN_EXISTING`, `UPGRADE_EXISTING`, `BUILD_NEW`, `PROJECTION_OVER_EXISTING`,
   `RESEARCH_CONTEXT_ONLY`, or `REJECTED_BY_DESIGN`;
2. there are zero `UNKNOWN` and zero `UNOWNED` paid capability rows;
3. every non-rejected row names its canonical workstream/owner, target Mastermind
   object or user journey, data/source/rights needs, authority class, and proof state;
4. `REJECTED_BY_DESIGN` is exceptional and must name the exact conflict (duplicate
   authority, rights/legal/commercial constraint, unsafe semantics, or vendor defect)
   plus how the underlying useful user job is otherwise satisfied when applicable;
5. the broader 1,556-row public inventory is reconciled into capability families so
   useful jobs/states are not lost while duplicate UI permutations are not mistaken
   for independent systems;
6. every built/upgraded/projection family that claims product value has a real
   consumer and production proof at its promised authority tier; and
7. learning instrumentation distinguishes product usefulness from prospective alpha
   value so descriptive/context features can remain useful even when alpha-null.

## Parallel execution law

Fable owns the remainder program as a sustained principal builder. Fable may mint
multiple simultaneous bounded operator commissions after a fresh collision census
when they do not contend for the same canonical owner/path/contract/authority seam.
A shared architecture does not require serial work. Dependencies still matter: a
lane may research, freeze contracts, build projections, or prepare tests while a hard
runtime dependency is closed, but it may not fabricate the missing prerequisite or
create a parallel truth plane to bypass it.

Sol retains architecture, authority, rights/commercial exception, cross-owner
collision, promotion, and final-acceptance jurisdiction. Ordinary implementation,
tests, reversible repairs, source archaeology, UI projection, real-data proof and
bounded worker orchestration belong to the COO inside the frozen envelope.
