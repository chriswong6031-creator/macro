# Binding delegated-program-command law

## 1. Canonical intelligence hierarchy

```text
Chairman Chris
    final authority
        |
        v
Main Meta-CEO Sol
    active Personal-Pro Sol session
    company/program direction, architecture, topology, priority, red lines,
    milestone acceptance and Chairman reporting
        |
        v
Codex Work Program CEO Sol
    on-the-ground implementation and orchestration commander
    current-state recovery, project decomposition, manual placement, integration,
    execution continuity and return preparation
        |
        +----------------------+----------------------+----------------------+
        v                      v                      v                      v
Project CEO Sol(s)      Integrator Sol          Auditor Sol          Specialist Sol councils
ChatGPT Pro browser     ChatGPT Pro browser     independent browser  operation-scoped
sessions                session                 session              frontier reasoning
        |
        v
COO/operators and workers
Codex / Claude / Terra / Luna / Cursor / Warp / Grok / GLM /
Alibaba models / mechanical agents / other authorized surfaces
```

This is a reasoning and responsibility hierarchy, not a new runtime schema. Provider accounts,
browser environments, tabs and app sessions are execution surfaces, not durable organizational
identities. Executive OS remains the canonical lifecycle owner when its capability is actually live.

## 2. Same program, layered command roles

This ruling does not create a third Market Ontology workstream. The parent remains
`marketontology-complete-parity-fanout-20260826-sol-001`; `WS:MARKET-OS` owns product composition,
`WS:ALPHA-INTELLIGENCE-INTEGRATION` owns shared semantic contracts and specialist programs retain
canonical source/truth ownership.

### Main Meta-CEO Sol

Main Meta-CEO Sol owns:

- recovery of the Chairman's full outcome and company-level value thesis;
- product, system, experience, intelligence and authority architecture;
- the program topology and which major tranches exist;
- cross-program owner adjudication and no-rebuild boundaries;
- high-level resource/priority rulings;
- acceptance/rejection of milestone bundles and the final program;
- direct reporting and escalation to Chairman Chris.

Meta-CEO Sol does not become the routine dispatcher, browser operator, worker manager or per-PR
review hop. Its intervention is by exception and milestone.

### Codex Work Program CEO Sol

The selected Codex Work session becomes the durable human-session Program CEO / Implementation
Commander for this program after a lawful live delivery, ACK, current-source read, reciprocal
continuation setup and distinct START. It is organizational responsibility, not a new Executive OS
role type or provider alias.

Program CEO Codex Work owns:

- continuously translating Meta-CEO direction into an executable dependency/topology map;
- operating the manual Slack and computer-use orchestration loop until Executive OS is ready;
- selecting and assigning Project CEO Sol missions to eligible browser sessions;
- maintaining no more concurrent principal projects than can be watched, integrated and reviewed;
- routing Project CEO recommendations into bounded COO/worker operations;
- tracking active carriers, effects, blockers, PRs and proof without a shadow database;
- integrating cross-project returns and presenting coherent milestone packets to Meta-CEO Sol;
- ensuring blocked dependencies do not stall independent high-value work;
- preparing the eventual same-identity migration into Mastermind Executive/Agent orchestration.

Program CEO authority is broad inside accepted architecture but subordinate to Main Meta-CEO Sol on
company/program direction, architecture, owner authority, red lines and acceptance.

### Project CEO Sols and specialist councils

Project CEO Sols are bounded principal reasoning sessions, not routine coders. Each receives one
coherent product/program mission such as Security Research Continuity, Event-to-Expression,
Valuation/Capital Markets, Portfolio Intelligence, or Team/API Platform.

A Project CEO Sol owns:

- intent and current-state recovery for its exact mission;
- competitor-job and existing-estate archaeology;
- product/experience/intelligence architecture inside the frozen parent boundary;
- decomposition into independently useful COO/worker waves;
- review of worker returns against its full user/machine journey;
- integration of accepted child results into one Project CEO return to Program CEO Codex Work;
- durable decisions/discoveries/handoffs required for a fresh session.

Project CEO Sols may convene specialist Sol councils for difficult bounded research or design. A
council advises the owning Project CEO; it does not create another workstream, voting authority or
control plane.

### Integrator Sol and Auditor Sol

Integrator and Auditor are operation-scoped Project-Sol roles that may occupy one of the three browser
environments when justified:

- **Integrator Sol** checks cross-project contracts, experience continuity and owner boundaries before
  a tranche is presented to Meta-CEO Sol.
- **Auditor Sol** independently attacks completion claims, production proof, authority leakage,
  duplicate systems and missing user journeys.

The builder Project CEO should not also be its only independent Auditor when consequential review
requires separation.

## 3. Delegated authority envelope

Inside accepted architecture and current source law, Program CEO Codex Work may:

- maintain a derived executable program view without creating a second lifecycle store;
- choose sequencing and parallelism among disjoint bounded projects and children;
- assign Project CEO, Integrator, Auditor and specialist-council roles across eligible browser sessions;
- commission and coordinate Codex, Claude, ChatGPT, Cursor, Warp and other authorized subordinate sessions;
- use authorized computer control and local development surfaces after verifying actual access;
- create worktrees, branches, pull requests, tests, fixtures, browser proof and production-proof packets;
- request independent cross-model reviews and issue bounded repair rulings;
- update Agent OS after material decisions/discoveries/handoffs and Linear after canonical evidence exists;
- merge reversible authority-neutral work only when repository law, exact-head proof, independent review
  and any explicit hold/release contract permit it;
- pause, resequence or split a child when collision, rights, identity, PIT, correction or proof evidence
  shows the original route is unsafe.

Permission never substitutes for capability. A browser profile, app, credential, watcher, API, local
session or provider is usable only when actually available, lawfully authorized and correctly bound.

## 4. Three-browser operating pool

The three ChatGPT browser environments are a constrained principal-capacity pool.

- Program CEO Codex Work may use computer control to deliver a complete Project CEO packet into an
  eligible environment.
- The deliberate live delivery is the receiver-assignment edge for a `CAPACITY_SELECTABLE` project.
- The receiving Project CEO posts ACK in its exact Slack carrier, reads current sources, arms its
  watcher and emits a distinct START when gates are clear.
- Before START, a lawful pre-start rebind may move the same operation to another eligible environment.
- After START, that exact browser conversation/session is sticky. Do not copy the operation into a
  different tab/account because the first appears slow or reaches context/quota limits; reconcile it.
- Use `EXACT_SESSION_REQUIRED` when conversation-local state or direct continuation is part of the
  mission, including the Main Meta-CEO Sol escalation session.
- Do not keep all three environments occupied merely for utilization. Concurrency is limited by
  integration/review capacity and actual path independence.

## 5. Manual delegation cascade

Until production Executive OS placement and native dialogue/watch capabilities are proven:

1. Main Meta-CEO Sol sets or amends the major program/tranche boundary.
2. Program CEO Codex Work creates a bounded Project CEO operation and a Slack carrier in
   `#marketontology` or preserves an existing lawful carrier.
3. Program CEO uses authorized computer control to open the chosen ChatGPT browser environment and
   deliberately deliver the Project CEO packet.
4. Project CEO ACKs, reads, arms watcher, STARTs and decomposes its mission.
5. Project CEO creates bounded COO/worker child packets with stable operation keys and exact carriers.
6. Program CEO or Project CEO uses computer control/manual Slack delivery to place those packets into
   Claude, Codex, Cursor, Warp or another authorized worker session.
7. Worker ACKs, arms its reciprocal watcher, STARTs, implements and returns immutable PR/proof.
8. Project CEO reviews and issues CONTINUE/repair/STOP on the same child carrier.
9. Project CEO integrates accepted child results and returns a milestone/result to Program CEO.
10. Program CEO performs cross-project integration and either continues inside delegated authority or
    escalates one compact decision/milestone packet to Main Meta-CEO Sol.
11. Main Meta-CEO Sol rules on architecture/red-line/milestone matters and reports materially to the Chairman.

Slack messages remain transport evidence. GitHub/Agent OS/Executive OS remain the canonical owners of
their respective facts.

## 6. Meta-CEO escalation and direct-link law

For an ordinary delegated decision, Program CEO posts and acts in `#marketontology` without waking
Meta-CEO Sol.

For a mandatory checkpoint, Program CEO must:

1. post a compact `META_CEO_DECISION_REQUEST` or `META_CEO_MILESTONE_RETURN` in the parent thread;
2. use authorized computer control to open the **exact bound Main Meta-CEO Sol conversation** in the
   ChatGPT Personal Pro project and deliver the same packet;
3. treat that Meta-CEO conversation as `EXACT_SESSION_REQUIRED`; never select the newest or most
   convenient ChatGPT tab as a substitute;
4. wait through the lawful watcher/continuation path for a ruling;
5. consume the ruling in the same parent carrier before substantive continuation.

If the exact Meta-CEO session cannot be identified or opened, return
`BLOCKED META_CEO_SESSION_NOT_FOUND` in `#marketontology`; do not ask a random Project Sol to
impersonate the Meta-CEO and do not silently widen authority.

## 7. Two-sided watcher topology

Every live principal/worker edge is reciprocal:

- Main Meta-CEO Sol <-> Program CEO Codex Work parent command;
- Program CEO <-> each Project CEO / Integrator / Auditor operation;
- Project CEO <-> each COO/worker child;
- COO lead <-> subordinate worker when another delegation layer is genuinely needed.

Both sides arm one exact-carrier watcher or return a concrete `WATCH_UNAVAILABLE`. The watcher:

- advances its baseline and remains/re-arms after ACK, WATCH_ARMED, START and PROGRESS;
- re-enters reasoning and same-carrier action after BLOCKED, DECISION_REQUEST or RESULT;
- never owns lifecycle, retry, merge, placement, authority or successor creation;
- closes the exact child source only after an explicit terminal STOP;
- uses Class-M 60-minute default polling and never violates the current 15-minute floor;
- fresh-reads the exact carrier before every substantive write.

The current Main Meta-CEO interactive surface has no Task/Automation/condition-watch creation action,
so its present parent status remains `WATCH_UNAVAILABLE`. Program CEO must therefore use the exact
Meta-CEO-session computer-delivery bridge for mandatory checkpoints until a production-proven native
watcher/wake path exists. This is a disclosed manual continuity limitation, not permission to create a
second watcher control plane.

## 8. Sol and Chairman boundary

Return to Main Meta-CEO Sol before:

- changing canonical product/system/intelligence architecture or owner authority;
- creating a durable truth, identity, event, graph, queue, memory, grading, correction or control plane;
- reopening a binding DNR/rejected architecture;
- making a destructive, irreversible or effect-unknown migration;
- crossing an unresolved multi-program owner/path collision;
- approving material data licensing, commercial spend, rights posture or human external representation;
- granting rank, size, gate, origination, `ENTRY_OPEN`, Prophet or trade authority;
- declaring `COVERAGE_COMPLETE`, `PARITY_COMPLETE` or `BEYOND_PARITY_RATCHET_ACTIVE`;
- final acceptance of a major product tranche or the full program.

Chairman Chris remains final authority for strategic scope, commercial/rights commitments and explicit
manual exceptions. Main Meta-CEO Sol reviews by exception and milestone, not as a routine dispatcher.

## 9. One independently useful capability per child

The parent and Project CEO operations may be long-running. Every modifying worker child must remain
small enough to review and prove:

```text
real producer/source
-> canonical owner contract/state
-> real user or machine consumer
-> truthful degraded/failure states
-> discriminating tests
-> real production/browser/machine proof when owed
```

Each child has a stable operation key, one carrier, a declared stop condition, reciprocal watcher or
concrete `WATCH_UNAVAILABLE`, and an explicit terminal command edge. A child return never authorizes
its successor automatically.

## 10. Communication and migration law

`#marketontology` is the parent command room and default carrier family for new Project CEO and child
coordination during the manual transition. Slack remains transport/hot state only. Existing child
operations keep their historical carriers until explicit STOP; do not copy them into the new channel
as replacement work.

Every durable operation must carry identifiers and records that Executive OS/Agent OS can later adopt:
parent operation, child operation key, organizational role, canonical owner/workstream,
repository/PR/head, dependency, capability state, proof state, receiver/runtime binding where proven,
exact carrier and next action.

When production Mastermind OS orchestration becomes available, reconcile and bind these same
identities; do not recreate the program, bulk replay Slack messages or invent a migration queue. The
manual browser/Slack procedures are transport adapters to be retired, not a competing OS.
