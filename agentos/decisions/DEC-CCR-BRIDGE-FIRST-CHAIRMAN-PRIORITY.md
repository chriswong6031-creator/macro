## Bridge-first critical path

### P0 — Active-Session Dialogue

1. **ASD-A1 / MAS-125** — finish and accept the hermetic, storeless Agent Relay on the existing
   `sol/asd-a0a1-20260823` / Mastermind PR #125 carrier only. **Done:** accepted head
   `21361653a273b801b08caa7271daa68437f7b2fc` merged as
   `eb9910681a6db9f9675b25233c8865bb43325c32`; preserve it and do not rebuild.
2. **ASD-A2** — production least-privilege Slack transport canary on one exact bound thread after
   A1 acceptance. This proves real app identity/scopes/history/send/restart/effect-unknown behavior;
   it still does not wake sessions or create Executive authority.
3. **ASD-A3** — prove one real already-active, already-commissioned Fable project can send
   `DECISION_REQUEST` / `BLOCKED` / `RESULT` to Sol and consume `RULING` / `CONTINUE` / `STOP`
   without the Chairman copying message bodies.

ASD-A3 is the first accepted milestone at which Chairman copy/paste between active Sol and Fable
sessions is no longer part of the normal workflow.

### P1 — canonical CEO admission bridge

After ASD-A3 is working, complete the already-designed MAS-48 path rather than invent another command
transport:

`Personal-Pro Sol → fresh SOL_STATE → private Slack CEO carrier → Executive Relay → CeoIngress → existing ceo_intent.submit_intent → canonical Job receipt`.

QUEUED admission remains distinct from execution.

### P2 — true hands-free attention / wake

ASD deliberately assumes sessions are already active. A3 removes manual message carrying but does not
by itself eliminate every need to notice or resume an inactive session. After A3 and MAS-48 production
proof, commission one separate architecture wave for bounded attention and provider-session wake/resume.
It must extend Executive OS / accepted provider lifecycle, reuse canonical identities/lifecycle,
keep Slack transport-only, preserve one-carrier reconciliation, and create no Session OS.
