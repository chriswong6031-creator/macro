## Delegated continuation law

Fable may proceed from one accepted child to the next without a Sol edge only
because this current Chairman decision is the explicit parent authority. It
must still close each child dialogue explicitly and create a fresh operation /
carrier / pickup / START / watcher cycle for the next independent child.

Fable's parent program carrier remains active across child STOPs. Child watcher
sources are removed at terminal boundaries while the principal/program source
stays active.

## Principal session succession

No one provider conversation is expected to survive the full program. Before
context exhaustion, quota exhaustion or planned maintenance, the current Fable
principal must:

1. stop or park every child at a known effect boundary;
2. write a complete Agent OS continuation handoff and exact program ledger;
3. fresh-read the parent carrier and publish a `FABLE PRINCIPAL SUCCESSION`
   return containing current operation/carrier/effects/watchers and proposed
   successor criteria;
4. select/bind one eligible fresh Fable principal through the existing
   capacity/placement owner under a new principal-epoch operation key;
5. obtain successor ACK, read, watcher and separate START before the old
   principal terminally stops its principal-epoch source.

This is planned succession, not blind retry or carrier failover. Any
EFFECT_UNKNOWN blocks succession until reconciled.

## Final return

Fable reports directly to the Chairman at terminal completion with the exact
production/release identities, capability ledger, prospective evidence state,
remaining non-authorities and durable next observation date. Routine Sol review
is not a prerequisite for that return or for prior in-scope progression.
