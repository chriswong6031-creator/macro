# Grounds

This decision changes **execution routing**, not the frozen China Alpha product or
intelligence architecture. The architectural authority remains
`research/CHINA_ALPHA_INTELLIGENCE_MASTERPLAN.md` plus
`DEC:CHINA-ALPHA-INTELLIGENCE-ARCHITECTURE-FREEZE` and any later explicit
superseding DEC. This record supersedes only the old operational expectation in
`WS:CHINA-ALPHA-INTELLIGENCE.next_action` that every later China Alpha wave must
remain closed until a fresh Sol ruling. Chairman 2026-08-24 provides the missing
program-level ruling: those later waves may now be opened by Fable when their
frozen dependencies and proof gates are actually met.

## Delegated execution authority

Inside the frozen architecture, Fable may without a new Chairman/Sol round trip:

- recover current main, Agent OS, relevant owner workstreams, current PRs, and
  production receipts before each wave;
- select and commission bounded workers using `DEC:AGENT-ROUTING-CONTROL` and
  the current repository routing law;
- run independent research/review workers in parallel where authority/path/data
  dependencies are genuinely disjoint;
- split a planned wave into smaller independently useful verticals;
- resequence independent waves to exploit source availability, data accrual,
  worker capacity, or collision avoidance;
- substitute a stronger deterministic/statistical implementation method when it
  preserves the frozen semantic contract and records the deviation;
- defer, reject, or kill a family that fails rights, data-quality, incremental
  value, or product-utility tests instead of forcing it into the ranker;
- repair an ordinary bounded defect discovered by CI or production proof when
  the repair does not mint new architecture or authority;
- merge reversible authority-neutral PRs when repository law permits after
  exact-head checks, focused tests, full required CI, and an independent
  adversarial review; a merge changes the wave only to BUILT_NOT_PROVEN;
- inspect the next natural production run and record a receipt without asking
  permission to manufacture/rerun the lane; manufacturing data or a proving run
  remains forbidden unless separately authorized;
- update Agent OS workstream/discovery/handoff records and selective Linear
  projection after material work;
- continue immediately to the next dependency after proof, rather than waiting
  for Chairman to relay a new prompt.

Sol will review the resulting PR/evidence chain in **milestone bundles** for
program acceptance. The absence of a per-PR pre-merge Sol message does not turn
Fable into architectural authority and does not make a merged wave PROVEN_LIVE.

## Mandatory return-to-Sol gates

Fable MUST stop the affected lane and return a bounded reconciliation/ruling
packet to Sol before proceeding when any proposed action would:

1. change the frozen product thesis, four-model architecture, §15 no-rebuild
   boundaries, five milestone definitions, or canonical source-owner seams;
2. create a new persistent truth store, lifecycle/control plane, identity
   authority, event authority, queue/retry authority, candidate store, grader,
   scoreboard, or general-purpose evidence/memory runtime;
3. change rights/legal/commercial posture, purchase a data seat/feed, expose
   private agreement material, or reopen a settled no-buy without its named
   flip condition;
4. change `engine/china_board_rank.py` live authority, Prophet admission/timing,
   board membership, score/rank/gate/size/ENTRY semantics, or grant a family or
   model live ordering authority;
5. promote any C1-C5/L-track challenger, or change the §11.6 promotion gauntlet;
6. give LLM/model-generated synthesis trade-origination, ranking, gating, sizing,
   or deterministic truth authority;
7. reopen a DNR/kill/rejected-by-design law or charter a specialist lobe other
   than currently permitted S1 Bio/Medtech or S3 EV/Auto without the frozen flip
   condition;
8. require a destructive/irreversible migration, material new spend, or
   cross-program authority takeover;
9. reveal an ambiguity in point-in-time clocks, identity, correction semantics,
   null/coverage authority, or event dependence that cannot be resolved by an
   existing owner contract;
10. produce a repeated production falsifier that challenges the masterplan
    thesis or evaluation law rather than exposing a bounded implementation bug.

These are executive/architecture gates. Routine implementation uncertainty is
not one of them.

## Flexibility / course-change law

The program plan is a dependency graph, **not a rigid waterfall**. At every wave
boundary Fable may choose a different feasible next wave if it records:

- the prior planned frontier;
- the newly observed fact/collision/data constraint;
- why the new order preserves or improves the user/machine outcome;
- which dependencies remain satisfied;
- which frozen boundaries remain untouched;
- the new falsifier/acceptance proof;
- the exact continuation action.

A course change that fits that template is COO execution. A course change that
crosses a mandatory return gate is a Sol/Chairman decision.

## Reporting cadence

No per-turn Chairman report is required. Durable state is the report. Fable
returns to Sol only for a mandatory gate or at the following milestone bundles:

1. Institutional Discovery Release;
2. Professional Intelligence Release;
3. Corporate Reality Release;
4. Asymmetry Intelligence Release;
5. China Intelligence Rank vNext promotion decision/final program acceptance.

A milestone return must include every PR/merge/proof since the prior milestone,
capability-state changes, killed/deferred hypotheses, production receipts,
product proof, measurement results, unresolved risks, and the next intended
program frontier. Sol audits those PRs against the original outcome before the
milestone is accepted.

## Transport caveat

Until the Active-Session Dialogue / automated Sol<->Fable bridge is actually
production-proven, a Slack dispatch is transport visibility only. It does not
prove Fable ACK, execution, or completion. One external Fable/principal-builder
session must claim this durable packet. **After that one pickup, this decision
explicitly removes Chairman Chris from routine routing for this program.**
