# K3-D propagation hypothesis contract — decision record

See frontmatter. Binding operational consequences:

1. `economic_propagation.propagation_hypothesis/v1` is the ONLY lawful join
   record over Graph 1/2/3 owner evidence. New propagation-like objects must
   compose through it or supersede this DEC explicitly.
2. Economic propagation stays a record class, not a program key: no
   `economic-propagation` entry in `config/mastermind_programs.yml`, no fourth
   graph/store, no grade ledger (grading spine only).
3. `earnings_readthrough_hypothesis/v1` is reserved as the earnings-grain
   species; building it means specializing this contract, never forking it.
4. The participation/breadth generator refusal and the four binding kills are
   part of the wire format (const field + registry refusal row) — removing them
   is a contract break, not a config edit.
