# Binding architecture freeze

## 1. Outcome and user journey

The product job is not "add three pages." It is one continuous orientation journey:

```text
arrive before the U.S. session
-> know which observation cut is available
-> see what changed since the prior close
-> understand today's scheduled catalysts and cross-asset tensions
-> open the underlying dashboard or evidence owner
-> resolve an unfamiliar indicator or term in place
-> return to the same morning read without losing context
```

The machine job is equally explicit:

```text
current owner artifacts
-> deterministic freshness and null adjudication
-> Morning Orientation view model
-> public browser composition
-> stable reference slug
-> owner/source/caveat receipt
```

No generated prose, static page, or green CI result counts as the capability unless a real browser
user can complete that journey on current data.

## 2. Current capability ledger

```text
AI Daily Brief / EOD multi-market surface       PROVEN_LIVE
Deterministic context strip and forward calendar PROVEN_LIVE / existing surface
General Methodology page                         PROVEN_LIVE / factor-specific
Internal site semantic documents                 BUILT / INTERNAL_ONLY

Market Orientation integrated continuation       NOT_BUILT
```

The EOD brief must not be relabeled as morning-fresh. Internal documentation must not be relabeled as a
public glossary. Existing infrastructure is substrate, not completion.

## 3. One canonical product composition

### 3.1 Morning Orientation lives in the existing brief experience

The public entry remains the current AI Brief family. MOR-2 adds a clearly separate
`Morning Orientation / 盘前导读` edition or mode inside `aibrief.html`; it does not mint a second general
brief product or a rival `master_brief` schema.

The Morning edition is deterministic at birth. It may show, only where current owner artifacts support
it:

1. observation cut and freshness banner;
2. since-prior-close cross-asset moves;
3. rates, dollar, credit, commodity, and international context;
4. scheduled releases/events with exact time/source;
5. deterministic disagreement/attention flags from existing owners;
6. conditions to monitor, phrased as research watch conditions rather than orders;
7. the prior-close AI brief, separately labeled with its older as-of time;
8. links to exact underlying dashboards and Reference entries.

No new LLM call is required for MOR-2. A later model-generated morning synthesis would be a separate
promotion only after the deterministic journey is production-proven and its cost, source cut, prompt,
correction, and failure semantics are separately accepted.

### 3.2 One public Reference surface

Create one public `reference.html` family, not separate Indicator and Glossary truth systems. It has two
reader modes over one registry:

- **Indicators** — concrete market/macro measures currently exposed by accepted product owners;
- **Glossary** — broader market, macro, portfolio, options, valuation, and research vocabulary.

Search, family filters, alphabetic navigation, stable anchors, bilingual copy, related terms, and return
links are projections over the same entries. A visible term may link into Methodology or an owning
product, but Methodology remains its current owner.

### 3.3 Curated registry is a presentation contract, not truth

Preferred location after Project-Sol archaeology:

```text
config/market_reference.yml
```

An owner-adjacent equivalent is allowed only if a current accepted config/catalog owner proves better.
The registry is closed and deterministic. Each entry should carry at least:

```text
id / stable slug
kind: indicator | glossary
family
label_en / label_zh
short_definition_en / short_definition_zh
why_it_matters_en / why_it_matters_zh
unit_or_basis
interpretation_up / interpretation_down / interpretation_neutral where applicable
caveats_en / caveats_zh
owner_ref
source_refs
related_ids
authority_ceiling: reference_only
status: active | deprecated
```

A registry entry does not establish that an indicator is currently available. Live values remain owned
by their source engines and pages. The reference surface describes semantics and links to the owner; it
never copies live financial truth into a second store.

## 4. Source, time, null, and correction law

### 4.1 Required clocks

Morning Orientation must expose:

```text
market_session_date
observed_at / observation_cut
per-source as_of or known_at where available
generated_at
prior_close_brief_as_of when that brief is shown
```

`generated_at` is not market freshness. A page rebuilt at 08:00 ET from yesterday's artifacts must not
call itself current.

### 4.2 Source-state vocabulary

Every block resolves to one of:

```text
CURRENT
STALE_WITH_LAST_KNOWN
UNAVAILABLE
NOT_COVERED
NOT_YET_OPEN
```

Unknown or absent data never becomes zero, neutral, unchanged, calm, or a model guess. If the minimum
morning source set is not current, the page shows a typed not-ready state and the last-close context
separately; it does not silently fall back to an apparently fresh AM edition.

### 4.3 Corrections

Reference copy changes through reviewed source commits. Deprecated terms preserve stable anchors and
point to replacements. Source data corrections remain with canonical owners; the morning projection
rebuilds from corrected owner artifacts and does not rewrite their history.

## 5. Deterministic versus model-generated method

```text
Reference registry and rendering      deterministic / human-reviewed public copy
Morning freshness and source state    deterministic
Cross-asset deltas and ordering       deterministic owner-derived calculations
Calendar                              deterministic canonical event owner
Prior-close AI brief                  model-generated existing artifact, visibly labeled
New AM narrative                      NOT AUTHORIZED in MOR-1..MOR-3
Ranking / gating / sizing / trading   FALSE
```

Terms such as "risk-on," "stress," "tightening," or "divergence" may be displayed only when an existing
owner has already produced that typed state or when the view uses a plainly disclosed deterministic
comparison. The reference registry itself cannot originate a market state.

## 7. Experience architecture

The morning page must answer in five seconds:

```text
Is this current?
What changed?
What matters today?
Where do signals disagree?
What should I understand or watch next?
```

Required states:

- current populated morning;
- partially current morning;
- source unavailable;
- market holiday/weekend;
- pre-source-window not yet ready;
- stale last-known context;
- no scheduled high-impact events;
- definition found;
- definition not found;
- deprecated term with replacement;
- mobile, desktop, dark, light, English, Chinese.

Definitions open through stable anchors or a drawer/deep link without forcing the user to restart the
brief. Keyboard focus, back behavior, URL anchors, search results, and language switches preserve the
current task.

## 8. Rights and security

Only lawful existing public/internal-computed sources may appear. Licensed Research Vault prose,
external newsletters, competitor text, and internal repository instructions do not become public
reference content. Source URLs and owner refs are allowlisted. Reference rendering escapes all copy and
must not interpret markdown/HTML from the registry unless the existing safe renderer explicitly owns it.

`DNR:KILL-PUBLIC-INTERNALS` remains binding: no raw repo paths, internal model names, DNR labels, scoring
keys, provider credentials, secret-shaped strings, or operational instructions appear on public pages.

## 9. Instrumentation and learning

Use the existing first-party analytics owner. Add only bounded events/metadata needed to answer:

- Is Morning Orientation opened before the session?
- Which source blocks or owner links are used?
- Which definitions are opened from the brief?
- What search terms return no result?
- Do users return from Reference to the brief?
- Which freshness/degraded states occur?

No new analytics table, visitor identity, event bus, or telemetry store is authorized.

## 10. Acceptance and production proof

Every wave requires exact-head tests and independent review. The integrated product requires:

1. a real natural premarket build from current owner artifacts;
2. source-state and per-block clock receipts;
3. a deployed exact merge/deploy SHA;
4. authenticated and public-entitlement behavior as applicable;
5. desktop/mobile, dark/light, EN/ZH browser evidence;
6. deep-link and return-continuity proof;
7. stale, unavailable, holiday, no-event, unknown-term, and deprecated-term falsifiers;
8. explicit scan proving no raw internal docs or secret-shaped content is served;
9. evidence that no second data/model/reference/analytics plane was created;
10. row-by-row F00 capability-state update only at the proven tier.
