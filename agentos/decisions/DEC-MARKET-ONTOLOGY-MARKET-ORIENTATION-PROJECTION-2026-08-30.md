# Binding architecture freeze

## 1. One user journey

```text
arrive before the U.S. session
-> identify the observation cut and source coverage
-> see what changed since the prior close
-> understand today's scheduled catalysts and cross-asset tensions
-> open an owner dashboard or evidence source
-> resolve an unfamiliar indicator or term
-> return to the same morning read without losing context
```

The machine journey is:

```text
canonical owner artifacts
-> deterministic freshness/null adjudication
-> Morning Orientation view model
-> browser composition
-> stable Reference ID
-> owner/source/caveat receipt
```

A static page or green CI is not completion. A real user must complete the joined browser journey on
current data.

## 2. Capability state at freeze

```text
AI Daily Brief / EOD multi-market surface        PROVEN_LIVE
Deterministic context strip and forward calendar PROVEN_LIVE
Factor-specific Methodology                       PROVEN_LIVE
Internal site semantic documents                  BUILT / INTERNAL_ONLY
AM Edition premarket journey                       NOT_BUILT
Reference Indicators Library                       NOT_BUILT
General 200+ term public glossary                  PARTIAL / INTERNAL VOCABULARY ONLY
Integrated Market Orientation continuation         NOT_BUILT
```

The EOD brief cannot be relabeled morning-fresh. Internal documentation cannot be relabeled a public
glossary. Existing organs are substrate, not product completion.

## 3. Canonical product composition

### 3.1 Morning Orientation stays in the existing brief family

MOR-2 adds a clearly separate `Morning Orientation / 盘前导读` edition or mode inside `aibrief.html`.
It does not create a rival `master_brief` schema or general brief product.

At birth the Morning edition is deterministic. It may show, where current owners support it:

1. session date, observation cut, generated time, and coverage banner;
2. since-prior-close cross-asset changes;
3. rates, dollar, credit, commodity, and international context;
4. scheduled releases/events with exact time/source;
5. deterministic disagreement/attention states from existing owners;
6. research watch conditions, never orders;
7. the prior-close AI brief under its own older timestamp;
8. links to owning products and Reference entries.

No new LLM call is required or authorized in MOR-1..MOR-3. A future generated morning synthesis would
require separate cost, prompt, source-cut, correction, failure, and promotion review.

### 3.2 One public Reference surface

Create one public `reference.html` family with two reader modes over one registry:

- **Indicators** — concrete measures exposed by accepted product owners;
- **Glossary** — broader market, macro, portfolio, options, valuation, and research vocabulary.

Search, family filters, alphabetic navigation, stable anchors, aliases, related terms, deprecation, and
return links all project the same entries. Methodology and owner pages remain independent owners.

### 3.3 Closed reference contract

Preferred source location after current archaeology:

```text
config/market_reference.yml
schema: mastermind.market_reference/v1
```

An owner-adjacent equivalent is allowed only if current source proves a better accepted catalog owner.
The registry is public-copy configuration. Every published entry carries at least:

```text
id / stable slug
kind: indicator | glossary
family
label_en / label_zh
aliases_en / aliases_zh
short_definition_en / short_definition_zh
why_it_matters_en / why_it_matters_zh
unit_or_basis
interpretation_up / interpretation_down / interpretation_neutral where applicable
caveats_en / caveats_zh
owner_ref
public_source_refs
related_ids
authority_ceiling: reference_only
status: active | deprecated
superseded_by when deprecated
```

Both languages are required for publication. IDs and aliases are unique under normalized comparison.
Unknown owner/source refs, duplicate aliases, cycles in `superseded_by`, unsafe URLs, or missing caveats
for an indicator fail the build. A registry entry never proves that a live value is available and never
copies live financial truth into a second store.

## 4. Time, null, and correction law

Morning Orientation exposes:

```text
market_session_date
observed_at / observation_cut
per-source as_of or known_at where available
generated_at
prior_close_brief_as_of when shown
```

`generated_at` is not market freshness. Every block resolves to exactly one state:

```text
CURRENT
STALE_WITH_LAST_KNOWN
UNAVAILABLE
NOT_COVERED
NOT_YET_OPEN
```

Unknown or absent never becomes zero, neutral, unchanged, calm, or a model guess. If the minimum
morning source set is not current, the page shows a typed not-ready state and last-close context
separately.

Reference copy changes through reviewed commits. Stable anchors survive renames. Deprecated entries
point to replacements. Source-data corrections remain owner-native; the projection rebuilds from the
corrected owner artifact and does not rewrite owner history.

## 5. Method and authority

```text
Reference registry/rendering       deterministic / human-reviewed public copy
Morning freshness/source state     deterministic
Cross-asset deltas/ordering        deterministic owner-derived calculations
Calendar                           deterministic canonical event owner
Prior-close AI brief               existing model artifact, visibly labeled
New AM narrative                   NOT AUTHORIZED in MOR-1..MOR-3
Rank / gate / size / trade         FALSE
```

Words such as risk-on, stress, tightening, or divergence appear only when an existing owner produced
that state or the view discloses a plain deterministic comparison. The Reference registry cannot
originate a market state.

## 6. Three independently useful waves

### MOR-1 — Reference foundation and core indicator library

Capability: a reader can search or deep-link a public bilingual Reference page and understand every
core indicator used by Morning Orientation, including basis, interpretation, caveats, owner, source,
and related concepts.

Candidate paths after fresh census:

```text
config/market_reference.yml
scripts/build_market_reference.py
templates/reference.html.j2
templates/_navlinks.html.j2
focused tests and generated asset under existing source/site law
```

The first inventory is the complete orientation indicator set plus common cross-asset terms, not an
arbitrary count. MOR-1 may close MO-DELTA-010 only after deployed navigation and owner-link proof. It
does not close the 200+ term row.

### MOR-2 — Morning Orientation and continuation

Capability: before the U.S. session, a reader distinguishes current/stale/unavailable blocks,
understands since-close changes and today's catalysts, opens an owner or definition, and returns to the
same orientation state.

Candidate paths after archaeology:

```text
scripts/build_aibrief.py
owner-adjacent pure view helper only if necessary
templates/aibrief.html.j2
shared brief partial only if shared behavior truly changes
aibrief.js + paired site asset only if interaction requires it
existing workflow/schedule owner
focused tests
```

MO-PAID-011 closes only after an untouched natural premarket run and real deployed browser proof. A
manual fixture or midday build is not AM production proof.

### MOR-3 — 200+ term breadth

Capability: the same Reference surface contains at least 200 distinct, useful, reviewed bilingual
terms with stable IDs, normalized alias uniqueness, owner/source/caveat coverage, family navigation,
and no internal leakage.

MOR-3 expands the same registry in bounded reviewed batches. One canonical writer owns each batch.
MO-DELTA-011 remains PARTIAL until count, quality, accessibility, navigation, and production proof pass.

After all three waves, one integrated production acceptance updates the F00 ledger. No wave marks all
three rows complete from code existence alone.

## 7. Experience and failure states

The morning page answers in five seconds:

```text
Is this current?
What changed?
What matters today?
Where do signals disagree?
What should I understand or watch next?
```

Required states include current, partial, unavailable, holiday/weekend, pre-source-window, stale
last-known, no high-impact events, definition found/not found, deprecated replacement, mobile/desktop,
dark/light, and EN/ZH.

Definitions open through stable anchors or an accessible drawer/deep link. Focus, back behavior, URL
anchors, language, theme, scroll, and return context preserve the user's task.

## 8. Rights, security, and public-copy boundary

Only lawful current public/internal-computed sources may appear. Licensed Research Vault prose,
external newsletters, competitor text, and internal repository instructions never become public
reference content. Source URLs are allowlisted. Rendering escapes all registry copy and does not
interpret arbitrary HTML/markdown.

The accepted public-internals boundary remains binding: no raw repo paths, internal model names,
control labels, scoring keys, provider credentials, secret-shaped strings, DNR identifiers, or
operational instructions appear on public pages.

## 9. Learning

Reuse the existing first-party analytics owner to measure morning opens, owner/definition link use,
no-result searches, return continuity, and degraded states. No new analytics table, visitor identity,
event bus, or telemetry store is authorized.

## 10. Acceptance and production proof

Every wave requires exact-head tests and independent review. Integrated acceptance requires:

1. real natural premarket build from current owner artifacts;
2. source-state and per-block clock receipts;
3. exact merge/deploy SHA;
4. relevant entitlement behavior;
5. desktop/mobile, dark/light, EN/ZH browser evidence;
6. deep-link and return-continuity proof;
7. stale, unavailable, holiday, no-event, unknown-term, duplicate-alias, and deprecated-term falsifiers;
8. public-output scan proving no raw internals or secret-shaped content;
9. proof no second data/model/reference/schedule/analytics plane was created;
10. row-by-row F00 update only at the production-proven tier.
