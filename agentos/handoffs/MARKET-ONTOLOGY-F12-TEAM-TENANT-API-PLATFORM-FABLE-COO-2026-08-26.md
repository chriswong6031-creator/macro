## Contract / time / correction law

Stable opaque IDs and schema versions are mandatory. Modifying requests bind operation/idempotency key, caller/tenant scope and expected version; same semantic request repeats safely, conflicting reuse refuses. Webhooks carry event ID/version/timestamp, signed body, bounded retry and dedupe without becoming canonical event lifecycle. Revocation/role changes take effect at authoritative access time. Deletion/export state is explicit and auditable. Secrets never enter repo/log/chat/receipts.

## Method / failure law

Fail closed on tenant ambiguity, role/entitlement mismatch, stale expected version, idempotency collision, signature failure, replay, schema incompatibility, rights/redistribution block, deletion uncertainty, export partial state, secret-shaped logging or internal contract unavailable.
