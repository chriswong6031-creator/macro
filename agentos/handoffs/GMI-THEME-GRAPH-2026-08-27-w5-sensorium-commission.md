## Observable mission

For an accepted local/canonical ThemeState and optional relationship/cohort context, produce one deterministic display/research context packet whose named sensor legs show what the market/research substrate currently says—breadth/participation, price/cycle, leadership/concentration, attention/flow/crowding/hazard or other owner-approved measures—while preserving source, as-of, coverage, units, authority and explicit unavailable/stale states.

## Why it matters

The theme graph becomes materially more useful when a user can see not only “these names are related” but whether participation is broadening, leadership is concentrated, attention is rising, positioning is crowded, or market incorporation is incomplete. The moat is truthful composition of existing specialist organs, not another opaque signal score.

## Authority / precedence

Chairman completion freeze; accepted W3B/W3C/W4 contracts; current owner contracts for every candidate measurement; W2 null/caveat law; `config/synapse.yml` authority catalog; current rights registry; existing grading/alert/ranking owners.

## Exact scope

Use existing `theme_state/v1` named legs where they already cover a measurement; W5 adds sensor-context species only when an existing owner supplies a distinct lawful primitive and a real downstream consumer needs it. Compatibility/public projections go through existing publication owners. No new specialist calculation engine.

## Explicit non-goals

No magic Theme Score; no rank/size/gate/origination; no alert escalation; no recomputation of Radar/rotation/options/flow/attention/positioning; no new options/attention collector; no W6 standalone UI; no Graph-1 inference; no experimental reranking.

1. Resolve exact local/canonical theme + as-of cutoff and read accepted ThemeState.
2. Read each eligible sensor leg from its native owner using an explicit adapter/reader.
3. Validate identity, clocks, coverage, units, rights and correction state.
4. Attach the leg under a stable named type with native value/qualitative state and provenance; never normalize into one synthetic strength number unless an owner already supplies that exact governed metric.
5. Keep unavailable, stale, rights-blocked and unsupported legs explicitly typed.
6. Preserve differences between local and canonical theme context.
7. Attach cohort/relationship context by reference, not copied truth.
8. Emit a deterministic packet consumable by Neural Web/MarketOntology F04 and machine research tools.

## Data / time / null / correction law

Every leg carries owner/source ID, native schema/version, as-of/known-at, coverage denominator where meaningful, units/horizon, freshness state, rights/display tier and correction/reference identity. Null/unknown is not zero. Different units/horizons remain separate. Later corrections do not rewrite decision-time packets; later reads produce a new packet/belief.

## Method

Composition/validation is deterministic. Existing statistical owner facts remain statistical and retain native uncertainty. Model prose is optional display-only summarization after packet validation and must cite/point to the named legs; it cannot fill or reweight them.
