# F11 — Human Research / Thesis / RMS / Assistant · sustained Fable COO lane

**Operation key:** `marketontology-f11-human-rms-20260826-fable-001`  
**Linear:** `MAS-152`  
**Transport:** DELIVERY_ONLY until explicit ACK.

## Observable mission

Give analysts a durable investment-research memory where coverage, notes, ideas, thesis claims, evidence, assumptions, scenarios, catalysts, risks, open questions, confirmation/invalidation conditions, review dates and revisions stay connected to the same canonical security/case/evidence objects; Ask Mastermind/Workspace Chat can answer over those stable versions without silently writing truth.

## Object / journey law

One Thesis identity → append-only Revision lineage → typed Conditions (economic, market/path, source correction, timing expiry, portfolio constraint) → Monitor subscriptions/cadence → source-stamped Observations → review/revision/resolve/close/archive. RMS views project coverage/ideas/notes/catalysts/risks/reviews over these identities. Assistant/chat reads exact object versions and canonical evidence; write actions are explicit, permissioned and idempotent, never implicit from prose.

## Data/null/correction law

Human research state references canonical facts but cannot rewrite them. Source correction triggers review rather than editing historical belief. Unknown/open question remains unknown. Monitor last-attempt/success/error/output/coverage are durable. Stable object ID + expected version + operation key + read-after-write + library/index reconciliation apply to every durable update. Tenant/user ownership and privacy are explicit.

## Method / learning law

LLM is a grounded assistant, not fact/identity/authority owner. Claim evaluation uses the correct metric class: factual support/correction, binary calibration/Brier/log score, directional benchmarked outcome, interval coverage/score, process completeness/revision discipline. Investment P&L is separate from thesis accuracy. No analyst leaderboard or scalar “smartness” metric absent explicit future governance.

## Failure states

Fail/abstain on missing case/security identity, stale evidence ref, permission/tenant ambiguity, version conflict, partial write, monitor execution failure, unavailable source, source correction, assistant citation mismatch, hidden write intent or deletion/export uncertainty. A failed monitor cannot remain clear/current.
