## Child-wave continuation/watch protocol

For every child operation, before doing work:

1. `ACK <operation_key>` in the exact Slack thread.
2. Read the complete thread plus the immutable/current canonical refs named by Sol.
3. Arm the best truthful exact-thread watcher/wait mechanism available on the COO reasoning surface.
4. Reply `WATCH_ARMED <operation_key>` with mechanism, cadence/live-wait behavior, exact thread,
   trigger, duplicate-suppression behavior and terminal disarm plan. If none is usable, return
   `BLOCKED <operation_key> WATCH_UNAVAILABLE` rather than disappearing.
5. State a separate truthful `START <operation_key>` only when execution gates actually permit work.

Keep every `PROGRESS`, `BLOCKED`, `DECISION_REQUEST` and `RESULT` in that same child thread.
After every nonterminal return, re-arm the exact-thread watcher. On Sol `RULING`, `CONTINUE` or
`REQUEST_REPAIR`, reread the complete thread, continue the same child/carrier, and re-arm after the
next nonterminal return.

When Sol sends `STOP — <operation_key>` / `SOL ACCEPTED`, the child is terminal: stop work, disarm
the watcher, end the child session/responsibility and reply only if watcher shutdown fails. Report
that as `WATCH_STOP_FAILED` without reopening the child. Any next child requires a new stable
operation key and fresh exact Slack carrier even when the same Fable seat continues the program.
