## Complete machine journey

1. Caller supplies a **requested canonical security identity** and a compile cutoff,
   not a free-form ticker as authority.
2. Adapter uses the institutional owner's bounded catalog discovery/read APIs to
   resolve an exact report-period generation at or before the cutoff.
3. It reads the manifest-bound holdings bucket/object, verifies digest/length, and
   selects the exact security row without broad prefix listing.
4. It binds row → exact generation → source receipt/accession → filer/manager
   identity and preserves every owner clock/rights/coverage field.
5. Stock Identity/Data OS resolution binds the row to the requested canonical
   security. Unresolved or conflicting identity yields typed refusal/unavailable.
6. The adapter constructs/reuses the full accepted K1 EvidenceRef; no local
   mini-pointer or caller-trusted provenance replaces it.
7. For Manager Research Intent, obtain a lawful `Q_prev/Q_now` pair for the same
   resolved complex/security and a reconciled public-sleeve denominator as required
   by K2-B. One-period data is `insufficient_history`, not zero intent.
8. K2-B alone derives the delta/context result. Adapter code cannot author the
   compiler result, reliability, score or conclusion.
9. Return a deterministic receipt naming exact owner generations/refs and typed
   state. Persist no copied owner payload and no aggregate truth store.

## Data / contract / time / null / correction law

- `report_period` is valid-time context, **never** knowledge/availability time.
- Operational knowability is no earlier than the later of owner `accepted_at` and
  `retained_at`; use the stricter accepted K1 clock when applicable.
- Every selected row must be bound to exact catalog generation identity plus its
  manifest/object digest, exact source receipt/accession and requested security.
- Current-pointer convenience cannot rewrite historical compilation. Historical
  reads must select a generation that was knowable by the requested cutoff.
- Amendments/corrections are append-only. A later correction supersedes an earlier
  observation only from the correction's own knowable clock onward; it cannot
  rewrite a prior as-of result.
- Missing row, missing predecessor period, unavailable source, rights block,
  unresolved identity, multiple incompatible rows, digest mismatch, generation
  ambiguity or stale/unusable correction must be typed explicitly and fail closed.
- `null`, `unknown`, `not_yet_knowable`, `insufficient_history` and `rights_blocked`
  are not interchangeable and none may be converted to numeric zero.
- Do not infer conviction from ownership size or manager brand. A professional
  manager remains an evidence-producing agent, not an oracle.

## Failure states

Hard-stop or typed-refuse on:

- owner-store/authentication unavailable for required real proof;
- current/historical generation missing or ambiguous;
- manifest/object digest or byte-length mismatch;
- selected holding does not bind exact source receipt/accession;
- security identity unresolved/conflicting;
- `Q_prev/Q_now` cannot be established without hindsight;
- rights/coverage/missingness says the source cannot be used;
- later amendment/correction would be applied before its knowable time;
- partial owner read, timeout or unknown effect;
- implementation needs owner-code, store, schedule, identity or authority widening;
- unexpected K2-C carrier appears after this commission.

Never blind-retry an effect-unknown modification. Never create a second carrier to
work around a blocked owner or credential.
