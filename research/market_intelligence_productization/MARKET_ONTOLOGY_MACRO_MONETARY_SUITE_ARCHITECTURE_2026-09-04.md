# 1. Executive ruling

## 1.1 One Macro Causal Operating System, not twelve isolated dashboards

The user journey is continuous:

```text
orient to current state
-> identify what changed
-> inspect drivers, contradictions and exact source clocks
-> distinguish fact, association, supported mechanism and hypothesis
-> replay honest history
-> test a bounded scenario
-> create a governed alert
```


Missing values never become zero, neutral, calm or unchanged. Measured zero remains a valid value.

## 6.4 Correction and comparability

- Preserve first-known historical state.
- Later revisions append correction/supersession lineage; they do not rewrite the original live observation.
- A state comparison is allowed only when subject, definition, data/model method and required denominator are comparable.
- Method change without a lawful bridge yields `COMPUTATION_REFUSED`, not a fake delta.
- Historical views label current-revised history separately from historical-as-known data.

## 6.5 Evidence and AI classes

Every implication is exactly one of:

```text
DESCRIPTIVE
HISTORICAL_ASSOCIATION
MECHANISM_SUPPORTED
MODEL_HYPOTHESIS
```

Deterministic state and changes cite exact owners. Statistical outputs retain model/version/sample/uncertainty and begin context-only. LLMs may explain accepted snapshots with citations; they cannot originate the core state or authority-bearing action.

Composite axes require documented components, transformations, units, weights, coverage thresholds, confidence method, version and negative controls.

Minimum scenario receipt:

```text
scenario_id / workspace / base_snapshot_digest
assumptions with units and bounds
owner/model versions
computed outputs and uncertainty
unsupported/refused assumptions
authority=false
```

Reuse the existing alert lifecycle. A macro alert is a condition over a canonical field/state, not a second monitoring service. Alerts preserve user, subject, threshold/state, owner field, freshness requirement, trigger identity, correction behavior and idempotency.

## 7.3 Learning

Use the existing first-party event owner to measure:

- workspace open and return;
- component/evidence drilldown;
- history/scenario/alert use;
- Reference and continuation links;
- degraded-state encounters;
- Analyst invocation/refusal;
- whether the workflow improves research continuation and retention.

Telemetry does not prove investment efficacy or grant authority.
