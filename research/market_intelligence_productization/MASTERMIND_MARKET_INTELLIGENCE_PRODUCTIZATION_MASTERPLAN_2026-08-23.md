# 4. Core object ruling

## `security_state.v1`

This is the compact current state of **every supported security**.

It belongs to Market OS and is published additively inside the existing stockdata/security plane.

It may contain references to current owner outputs, but it owns no new rank or source truth.

It answers the shared Decision Spine:

```text

Change
Opportunity context
Risk

```

## `OpportunityCase`

This is the future Alpha Intelligence K5 synthesis identity for a **specific live research opportunity or unresolved reality-vs-market-belief disagreement**.

It does not exist for every security at every time.

It references:

```text
reality
evidence blocks
transmission
market incorporation
company context
path/timing
portfolio intersection
strongest unresolved fact
failed gates
next observables
evaluation
```

Its prose never feeds Prophet ranking.

## Relationship between the two

```text
security_state.v1
    compact current state for every supported security
    optional opportunity_case_ref

OpportunityCase
    deeper episodic research synthesis when a lawful case exists
```

Neither replaces the other.

## Projection names only

The following are projections, not truth objects:

```text
RetailDecisionPacket
DeskResearchPacket
PortfolioCaseView
PublicGlance
ThesisContext
```

`MarketCase` may be used as a product/read-model label only if K5 preserves the same underlying `OpportunityCase` identity.

Do not mint parallel MarketCase, DecisionPacket, TradeCase, and OpportunityCase truth stores.

# 10. Authenticated Market Ontology acceptance laws

Every implementation wave inherits:

## Aggregate denominator receipt

Print total, included, excluded, missing/fallback/stale shares, basis, timestamps, and reconciliation state.

## Dominant degradation

A materially partial denominator makes the affected panel partial/degraded/abstaining.

## Idempotent updates

Stable object ID + expected version + operation key. Edit never becomes add.

## Durable execution receipts

Last attempted, last successful, state, error, coverage, output version. Failure never looks `clear`.

## Write/read-model reconciliation

A saved object is accepted only when detail and canonical library/index agree.

## Confidence/probability receipt

Meaning, source, inputs, calibration, sensitivity, version, and authority—or display-only/uncalibrated.

## Partial computation cannot look complete

Missing data does not become zero or neutral.

## Output-specific prerequisites

Only the affected output class fails when its prerequisites are unavailable.
