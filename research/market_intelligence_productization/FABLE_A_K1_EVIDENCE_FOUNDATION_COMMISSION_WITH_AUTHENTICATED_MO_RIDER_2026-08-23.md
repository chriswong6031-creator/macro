## `EvidenceRef`

A pointer to an owner-native object.

Required semantic fields:

```text
owner
native object ID
native schema/version
object class
subject-key type/value
owner-native clocks
digest or typed unknown
coverage/freshness
correction state
authority class
rights state
```

It does not copy the fact payload.

## `EvidenceBlock`

A consumer projection over one or more `EvidenceRef` rows and bounded owner-reader output.

Required fields:

```text
evidence_block_id
job/consumer
supported claim or question
owner refs
fact / deterministic / model / human class
clock summary without collapsing owner clocks
coverage and missingness
uncertainty
conflict/correction state
next observable
permitted consumer/authority
```

It is not a truth store.

## `EvidenceRecipe`

An ordered, versioned composition instruction for a specific consumer such as:

```text
security_state.v1
OpportunityCase
RetailDecisionPacket
DeskResearchPacket
```

A recipe states:

- required and optional evidence blocks;
- owner readers;
- identity joins;
- clocks;
- refusal/degradation rules;
- dedup/dependence rules;
- output field mappings.

It does not persist owner facts.

## Product integrity laws

The K1 contract must support:

- aggregate denominator receipts;
- dominant degradation;
- partial computation not shown as complete;
- explicit unavailable/conflicted/corrected states;
- confidence/probability derivation or display-only status;

# 9. Data, time, null, and correction behavior

## Time

Never replace owner-native time fields with a generic `as_of`.

A recipe may provide a display summary, but every ref retains:

- native field name;
- native value;
- clock class;
- grain;
- source/owner.

## Nulls

Use typed states:

```text
NOT_COVERED
NOT_APPLICABLE
UNAVAILABLE
RIGHTS_BLOCKED
UNKNOWN_CLOCK
UNKNOWN_DIGEST
STALE
PARTIAL
CONFLICTED
CORRECTED
```

Never substitute zero, empty list, epoch, or current time.

## Corrections

A correction creates a new owner-native version/ref or changes its correction state according to owner law.

Dependent EvidenceBlocks and recipes must be invalidated or recompiled with an explicit receipt.

Do not overwrite the old owner object or rewrite historical consumer output silently.

## Dependence and deduplication

Several references may share one upstream event/document.

K1 must preserve:

```text
economic episode / logical event relation
source-document dependence
owner observation distinction
```

No count of references is allowed to imply independent evidence.
