## 1. Architecture — the frozen-substrate pack + oracle-path evaluator

§7.1 mandates: the intraday lane never re-derives a signal from a mutable store; nightly threshold inversion; the stale-pack gate; degenerate cases explicit; path features from the 5-minute sampled snapshot stream (never raw minute lows). The design implements that law as follows.

**Nightly pack = the frozen evaluation substrate.** `scripts/entry_radar_live_pack.py` (VPS timer, off-RTH) builds one artifact for the next session carrying, per probe-set name:

- the **confirmed daily substrate verbatim** (adjusted OHLC through `as_of`, exactly what `DailyHistory` needs), frozen so a mid-session store move can never shift an indicator (§5 stale-pack row: a wrong-session series *fabricates* crossings);
- `as_of_close` (basis-audit anchor), `last_confirmed` session (per-name freshness), prior-confirmed ATR14, confirmed StochRSI K value (re-arm ledger input, C3 daily leg receipt);
- **solved inverted thresholds as first-class receipts**: `c1_arm_price` (K<20 boundary) and `c2a_cross_price` (K−D sign boundary), bisected against the same W3 oracle, with explicit `no_threshold_exists` degeneracy markers (flat-RSI NaN window, saturation, unreachable condition) — §7.1's two hardenings verbatim;
- pack identity: `schema`, `as_of`, `built_at`, `price_basis`, `pack_hash`, spec-hash table, embedded Probe Set snapshot (tickers + admission provenance) so the whole cycle shares ONE `as_of` gate.

**The RTH evaluator evaluates the frozen pack through the W3 oracle itself.** Each pass builds today's `Observation`s from the pack substrate + the journaled 5-min snapshot stream and runs the **unmodified** W3 evaluators (`run_c1`, `run_c2`, `run_c3`, `c4_snapshot`). Parity with confirmed-bar math is therefore *by construction* — the live lane executes the same functions the PIT battery proved. The inverted thresholds are cross-checked every pass: the oracle's C1/C2a booleans must agree with the threshold comparisons; disagreement is a `pack_integrity` refusal for that name (fail closed, never fall back).

This is the lawful synthesis of §7.1's two sentences: "no intraday indicator recomputation" binds against *re-deriving from a mutable store / a second implementation* — the pack freezes the substrate nightly and the only intraday computation is the O(1) evaluation of the frozen substrate at the observed price, through the byte-identical W3 code path; and "per-name price thresholds" ship in the pack, gate-checked live. No detector meaning changes; A5 semantics are executed verbatim. (Recorded here under A5.0's correction-protocol discipline as a mechanism receipt, not a spec change — no CEO return required because no firing-relevant semantics move.)

**Nightly threshold-inversion PROOF pack (commission amendment §2 — a falsification instrument, never parameter search).** Alongside the substrate, the pack builder runs a deterministic, bounded counterfactual battery and refuses to publish a pack that fails it. For each load-bearing frozen threshold — C1 `K<20` arm, C2a `K×D` cross, c2f `0.5×ATR` rebound, C3's 3-point turn predicate, the basis tolerance, per-name staleness, and the §10 re-arm rule (`K>50`×2 / 15 sessions) — the builder constructs lawful PIT micro-cases straddling the boundary in BOTH directions (prices/values just below, at, and just above the solved threshold; state micro-paths driven through the unmodified `run_c1`/`run_c2`/`run_c3`) and asserts the expected transition / refusal / null behavior, recording `{case, boundary, direction, expected, observed, pass}` per probe into `entry_radar_inversion_proof.json` (verification-only, PRIVATE_OPERATIONAL; summary counts ride the payload health block). Any failed case marks the pack `proof_failed` and the RTH evaluator refuses the whole cycle (fail closed) — an evaluator that disagrees with the frozen thresholds must not run. The proof pack tunes nothing, optimizes nothing, reads no forward outcome, ranks nothing, and never touches a spec hash.

**Incremental observation construction + byte-parity pin.** `build_observation_path` recomputes the oscillator chain per sampled point — exact but O(points²) per session if re-run per pass across ~1,500 names. The live lane therefore constructs only the NEW interval's `Observation` per pass (`sample_session_path` for path stats — cheap, no indicator math — plus one chain evaluation for the new tick, with the same availability/basis/freshness decisions). This is the one derived construction in W4, and it is pinned: `test_entry_radar_w4_live.py` asserts the incremental path is **byte-identical** (`canonical_readings`) to a full `build_observation_path` run over the same tape, across the fixture corpus including gaps, stale history, basis mismatch, early close. Any drift reds CI.

## 2. Data flow per pass (`scripts/entry_radar_live.py`, systemd `:04/5` ET RTH)

1. **Kill switch** (`ENTRY_RADAR_LIVE_DISABLED` env or kill-file in the state dir) → publish payload with `health.state="killed"`, exit 0. `ENTRY_RADAR_NO_PUBLISH` (W1) additionally refuses every write for rehearsals.
2. **Session window**: NYSE calendar + ET window with grace (shape of `live_states.in_window`, re-implemented from `lib/nyse_calendar` — Radar imports nothing from `engine/prophet_live` per the W1 leaf-discipline precedent). Outside → `health.state="out_of_window"`, no evaluation.
3. **Pack gate**: load pack; `pack.as_of != last_completed_session(now)` → whole-cycle `stale_pack`: every name `unavailable`, **zero transitions, zero spool** (§5 matrix row), payload + receipt say exactly that.
4. **Quotes**: read the shared snapshot artifacts (`/var/lib/macro-live/state/quotes_full.json` + fast overlay, freshest-wins — the same files prophet-live reads; Radar fetches nothing itself). Per-name quote age gate (`stale_quote`). Coverage counted against the probe set in the receipt; a probe name without a quote is `unavailable`, never dropped.
5. **Basis audit per name, BEFORE any evaluation** (W3-1 carried forward): `|pack.as_of_close − quote.prev_close| / as_of_close > tol` (0.25% convention, derivation cited from the prophet-live interval contract) → name `dark/basis_mismatch`, readings `unavailable` with `condition_met=None`, no evaluation. Audit receipt (gap, tolerance, both closes) rides every name row.
6. **Journal append**: the pass's per-name observation point (interval-mapped snapshot price, vendor ts, audit outcome) appended to the session journal (`/var/lib/macro-live/state/entry_radar/journal/…`). Journal rows are frozen at write and pinned to `pack_hash` — re-derivation with a different pack refuses (the mechanical no-backfill law).
7. **Derive**: per name, rebuild today's observation list (journal + pack, incremental construction §1), concatenate with journaled observations of prior sessions back to the live episode's arm session, and run `run_c1`/`run_c2` (+ `run_c3` for daily-leg-armed names via the bounded minute reader; `c4_snapshot` at C2a candidates). Deterministic: same inputs ⇒ same outputs; no wall clock in derivation.
8. **Ledger diff → spool-first → commit**: new events/transitions relative to the runtime episode ledger are spooled as ONE object (`live_flow/entry_radar_events/<session>/<HHMMSS>-entry_radar_live.json`, W1 `NominationSpool` mechanism with the events prefix — same code, second prefix, NOT a second queue). Spool success ⇒ ledger commit + payload inclusion. Spool failure ⇒ nothing commits, the payload reports `spool_failed`, next pass re-derives and retries (idempotent addresses make the retry safe).
9. **Payload**: `live/entry_radar.json` by mkstemp+rename into the `MACRO_LIVE_DIR` ladder (deliberately NOT in the Caddy allowlist — inherits the auth gate by omission). Full per-lane fidelity for any name with a non-PROBING lane; compact rows otherwise; all-false authority block; mechanical copy only.
10. **Health receipt** (§6 below) + heartbeat in the state dir.

**Episode clock overlay (session-boundary work, runs in the pack builder):** CANDIDATE → RESOLVED when H=10 sessions elapsed (stamped at the H-th session close; a lifecycle fact, no outcome attached — grading stays W5); ARMED/TURNING-without-candidate → EXPIRED at `C3_ARM_EXPIRY_SESSIONS` = 15 sessions, stamped at the expiring session's **open** (`run_c3`'s W3-2 convention) — the overlay is the SECOND lawful enforcement point for that frozen rule, because `run_c3`'s own clock is positional within the sessions its stateless replay walks and so can never reach a ledger episode armed outside that window (W4R-M8; the 15 is imported from `four_hour`, never re-minted); re-arm windows via `rearm_eligible(confirmed_k_since_end, sessions_elapsed)` fed from the pack's confirmed-K ledger; would-be arms during an ineligible window are recorded `suppressed_by_rearm` (§11 control-pool flag), never silently dropped. C2 episode unit is (ticker, detector, **variant**) exactly as W3 shipped (JC2). INVALIDATED remains a legal state with **no W4 producer** — the frozen contract defines no intraday invalidation rule; inventing one would be a firing-semantic change (A5 correction protocol). G0/C5 are confirmed-bar lanes evaluated at pack build from the Terminal slice store when reachable (`nightly · confirmed` stamps), honestly `unavailable` otherwise.

## 6. Health receipt (deterministic, enumerated)

`payload.health = {state ∈ {live, degraded, stale_pack, proof_failed, out_of_window, killed, failed}, reasons: [...], pass: {seq, evaluated_seq, at, prev_at, expected_next, prev_gap_intervals}, inputs: {quotes: {asof, age_s, coverage: n/probe_n, stale_n}, pack: {as_of, pack_hash, fresh: bool, proof_failed: bool}, spool: {ok, key|error}, c3_reader: {fetched_n, cache_hits, errors, empty, deferred_n, incomplete_n, reader_fetched_n, reader_cache_hits, reader_errors, reader_empty}}, basis: {audited_n, mismatched_n, unchecked_n, refused: [tickers]}, null_readings: {reading_unavailable, reading_stale, suppressed}, dark: {reason → n, one key per NAME_REFUSALS entry}, content: {last_transition_at, events_total, ledger_hash}}` — `content.last_transition_at`/`ledger_hash` is the content-advance signal (green process ≠ current is answered by `pass.at` + quote asof + content hash all three). Evaluator failure = service exit ≠ 0 + heartbeat age + sentinel breach (three independent detectors). The freshness-sentinel SURFACES entry reads the payload with an RTH-aware SLA; silence pages through the existing sentinel plane, not a new one.

**Seven states, not six.** `proof_failed` is carried separately from `stale_pack` even though both refuse the whole cycle: a pack whose inversion-proof battery (§2 above) failed is a different operational fault from a pack built for the wrong session, and collapsing them sends an operator to the wrong lane. The producer is the §2 step-3 gate; `HEALTH_STATES` in `engine/entry_radar/live_eval.py` is the mechanical copy and `CYCLE_REFUSALS` names which five refuse the cycle.

**`pass.seq` counts PASSES; `pass.evaluated_seq` counts EVALUATIONS.** The heartbeat is written on every terminal path including the five whole-cycle refusals, so "ran 78 times and refused all of them" and "did not run at all" do not leave the identical trace — a lane that is killed and a lane that never fired must be distinguishable, which is the same failure signature the render-cancel rule exists for. `evaluated_seq` keeps the narrower reading available for anything that wants "how many passes actually looked".

**`c3_reader` is TWO counter sets, namespaced.** The unprefixed keys are the ones the PASS owns (`fetched_n`, `errors`, `deferred_n`, `incomplete_n`), the `reader_*` keys are the reader's own, and they are never merged over each other. The reason is load-bearing: `VendorMinuteReader.errors` increments only on a TRANSPORT raise, so an aggregation or mixed-timezone fault — the ones the bucket builder's own docstring warns about — left it at zero, and a blanket merge destroyed the honest pass-local count and with it the `c3_reader_errors` health reason. `empty` (a response that parsed but held no bars) and `cache_hits` (a bucket served off disk) are facts only the reader can report, so they are folded in unprefixed as well as namespaced. `deferred_n` counts names the §2 C3 budget postponed; `incomplete_n` counts names refused `c3_incomplete_window`. The whole block is in `VOLATILE_PAYLOAD_PATHS`: a warm bucket cache legitimately turns `fetched_n` into `cache_hits` between two runs of the same cycle, so a determinism assertion built on it would flake — an error or a deferral is a NAMED health reason and those stay in the content hash.

**`null_readings` is what makes `live` a narrow state.** A pass in which every evaluated name returned a null reading (`availability` unavailable or stale, or a suppressed arm) used to report `live` with an empty `reasons` list: `health.dark` counts dark names, and a null reading is not a dark name. `live` now additionally requires at least one reading that is a real measurement; an all-null pass carries `reading_null:{n}/{evaluated}` and is `degraded`. This is the §0 null law (`missing != false`, `stale != non-fire`) reaching the one surface an operator actually reads.
