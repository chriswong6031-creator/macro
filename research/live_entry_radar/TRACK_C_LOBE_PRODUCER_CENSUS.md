## 3. Gaps

- **state_of_themes.html, radar.html, foresight.html carry no single-name producer at their primary display level** — all three are theme/basket-scored, not ticker-scored. Any nomination use would have to go through a SEPARATE artifact (`narrative_emergence.json` recommended tickers, or basket `membership.json` expansion), never the page's own headline data.
- **No systematic ETF/ETN/leveraged-product classifier** for an arbitrary lobe-nominated ticker (see §2) — a name surfaced by any producer above could be a 3x leveraged ETN with nothing in the current estate flagging it before nomination.
- **No float-based share-turnover computation found** — existing liquidity proxies (`dollar_vol_20d`, `rel_volume`) are volume-vs-own-history, not volume-vs-float/shares-outstanding.
- **Gap detection exists but is dormant** (`engine/entry_primitives.py:651`, appendix-locked, not live-wired) — would need to be un-gated and integrated, not built fresh.
- **`engine/entry_primitives.py`'s entire full-history series layer is "DISPLAY/RESEARCH ONLY... wires into nothing live"** (module docstring) — every full-history primitive (rel_volume_series, gap_hold_events, realized-vol series) needs a live-wiring decision before an entry radar could depend on it; only the point-in-time snapshot half (`engine/stock_technicals.py`) is currently live.
- **capital_structure.html is API-gated, not artifact-based** — a nomination adapter for it needs an authenticated API integration, structurally different from every other row's "read a committed JSON/parquet" pattern.
- **theme graph (GMI) cadence is unverified / likely not-yet-automated** — no workflow reference found; treat as a research-stage source, not a reliable nightly feed, until confirmed otherwise.
- **Two parallel sector-mapping stores** (`data/breadth/ticker_sectors.parquet` GICS-authoritative vs `data/sp500_heatmap/industry_map.json` Finviz-curated) — not cross-checked for drift in this pass; a nomination adapter picking the wrong one risks a sector label mismatch vs the rest of the site.
- **Hot Tape radar (#28) — the highest-frequency single-name detector in the repo (5-min) — has no `data/` artifact at all**, only a marketing outbox write. A nomination adapter would need a NEW tap on `engine.marketing.hot_tape.detect_events()`'s in-memory output, not a file read like every other row.
- **`site/stockdata/<T>.json` population is inconsistently sized across consumers**: `universe()` stamps ~2,966 names nightly, but only ~1,595 get full dossier pages (`build_ticker_pages.py`) — a nomination adapter must confirm which count a given field (e.g. `entry_signal`) actually has coverage over before assuming universal presence.
- **Options family (`options.html`) has no single unified per-symbol store** — GEX (`site/gex/index.json`), screener (384/353-name parquets), flow leaders, and flow desk are four separate builds with overlapping but non-identical universes; a nomination adapter integrating "options confirmation" must pick one or reconcile.
