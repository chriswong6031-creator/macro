# 1. Observable mission

Design and, after lawful owner routing, implement the scientific acceptance system that answers:

> Did this new intelligence family make Prophet meaningfully earlier, more selective, safer, better ranked, more actionable, or more useful — on an honest point-in-time tape — and what maximum authority has that evidence actually earned?

The measurement system must prevent a family from appearing superior merely because it:

- waits until the move is obvious;
- narrows to a tiny favorable coverage cohort;
- changes the candidate population and then compares non-comparable rows;
- benefits from current/final-corrected history;
- chooses horizons/labels after results;
- overweights repeated observations from a few issuers/themes/dates;
- passes a retrospective backtest but has no forward evidence;
- improves precision while destroying earliness;
- adds explanation value and is then incorrectly promoted as alpha.

- Did Theme Transmission find winners before C1, or merely explain them later?

This measurement history is itself compounding proprietary intelligence.

# 6. Preliminary measurement architecture to attack, refine or reject

## G-P1 — Early Actionable Winner Capture is a metric family, not one magic scalar

Start with separate dimensions.

### A. Earliness

**First Eligible Surface**

Earliest decision session at which the frozen candidate system could lawfully surface the episode.

**Lead Time vs Champion**

```text
lead_sessions = champion_first_surface - challenger_first_surface
```

Positive = challenger earlier.

Same episode, same decision-clock semantics.

### B. Actionability

**Actionable at First Surface**

Was independently owned deterministic Availability `ENTRY_OPEN` at first eligible surface?

**Opportunity Consumption at First Surface**

Candidate confirmatory/live-knowable measures:

- distance from frozen entry-zone/chase boundary;
- ATR-normalized move since registered evidence/episode start;
- availability state/duration.

Candidate descriptive-only measure:

- fraction of eventual MFE already consumed, because eventual MFE is future knowledge.

Cell G must freeze what is confirmatory vs descriptive.

### C. Ranking

- NDCG@K;
- precision@K;
- recall@K;
- first-surface rank of later positive-path episodes;
- rank stability/churn;
- opportunity-weighted retrieval where lawfully defined.

### D. Path quality

- MFE;
- MAE;
- R;
- time to +0.5R/+1R where defined;
- time underwater;
- invalidation;
- false bounce;
- tail loss.

### E. Coverage / estimability

- eligible population;
- covered population;
- covered-vs-uncovered characteristics;
- unique issuers;
- unique date clusters;
- effective N;
- refusal counts;
- family coverage state.

### F. Product/human value

- review volume;
- action/watch/pass/reject behavior;
- explanation drill-down;
- later correction/override rate;
- repeated user rejection reasons;
- time/effort burden if measurable.

Do not combine all six blocks into a single score initially.

## G-P2 — “winner” is registered, not hand-curated

Core reports should prefer continuous outcomes.

If a thresholded winner/positive-path label is needed:

- register it before the outcome read;
- bind it to a horizon/ruler;
- show sensitivity across reasonable preregistered thresholds;
- never quietly change the threshold because a lobe barely misses.

## G-P3 — same-tape paired experiments are default

For family `f`:

```text
Champion(t)
ChampionMinusF(t)
ChampionPlusF_Shadow(t)      # when f is not in champion
ShuffledF_Placebo(t)
```

Use same episodes/clocks/availability where the claim is rank value.

If `f` changes candidate discovery/population, split the study into:

- **retrieval/discovery effect**;
- **ranking effect on shared candidates**.

Do not pretend they are one paired experiment.

## G-P4 — family value has at least four categories

1. **Discovery value** — surfaces a candidate champion missed or surfaced later.
2. **Ranking value** — orders shared candidates better.
3. **Risk/path value** — improves trap/tail/MAE understanding.
4. **Explanation/product value** — improves human reasoning without alpha.

A family may PASS one and FAIL the others.

## G-P5 — lead-time preservation is load-bearing

A challenger that improves precision by waiting for confirmation may be useful but is not automatically a flagship improvement.

# 7. Additional measurement problems Cell G must solve

## 7.1 Metric denominators

Every metric needs exact denominator semantics.

Examples:

- precision@K over what sessions and K when fewer than K candidates exist?
- actionable-at-first-surface over all surfaced episodes or only episodes with a valid availability computation?
- lead-time when champion never surfaces an episode?
- recall against which registered opportunity universe?
- correction events: preserve original decision-time classification or final truth?

No numerator without denominator law.

## 7.2 Retrieval vs ordering

A new family may create candidates that champion never saw. This is not measurable by a rank-only LOFO over shared rows. Cell G must design separate discovery metrics.

## 7.3 Missingness / coverage selection

A sparse lobe can look good because it covers easy names. Mandatory analyses:

- covered vs uncovered size/liquidity/sector/species/theme/volatility;
- performance of champion on covered cohort;
- missingness mechanism;
- whether coverage itself is predictive;
- explicit refusal to generalize beyond covered population.

## 7.4 Multiple testing / research garden

The flagship will test many families, heads, horizons, species and models. Cell G needs a practical policy for:

- preregistered primary claim;
- secondary/exploratory claims;
- repeated looks;
- family-wise or FDR control where appropriate;
- model-selection nested folds;
- reporting failed experiments so the organization does not repeat them.

The answer need not be one universal p-value threshold, but must stop free option value from endless experimentation.

## 7.5 Promotion vs demotion

Define not only how a family earns authority but how it loses it when:

- calibration drifts;
- data source changes;
- coverage collapses;
- later forward evidence reverses;
- an owner changes semantics/version;
- a dependence bug is discovered.

Authority should bind to version + population + evidence clock, not a family name forever.
