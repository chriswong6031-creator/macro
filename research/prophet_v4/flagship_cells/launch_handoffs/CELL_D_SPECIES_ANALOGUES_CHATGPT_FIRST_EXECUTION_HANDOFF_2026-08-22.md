# 7. Analogue retrieval contract — freeze before outcomes

The retrieval process must be reproducible from information available at the query decision time.

## Stage A — eligibility

An eligible historical episode must have:

- lawful episode identity;
- source/feature snapshot at its own comparison clock;
- valid identity/epoch or explicit reconstruction limitation;
- sufficient source quality;
- no future outcome fields in retrieval features;
- no later-corrected feature silently substituted for contemporaneous belief.

## Stage B — candidate pool

Hard filters should be interpretable and broad enough to retain counterexamples.

Possible filters:

- asset/venue;
- minimum liquidity/data quality;
- registered setup/expert family if appropriate;
- broad structural incompatibility;
- identity-era validity.

## Stage C — feature transform

Standardization, covariance, weights and embeddings are frozen on lawful training data. Target/future folds excluded.

## Stage D — similarity

Compare simple and auditable methods before learned metrics:

- standardized weighted distance;
- Mahalanobis where covariance is stable;
- hierarchical/hard-filter + soft continuous distance;
- learned metric only after OOS design.

## Stage E — missingness

Missingness is not similarity.

Required design properties:

- minimum feature overlap;
- missing mismatch penalty or family-specific availability logic;
- overlap-quality disclosure;
- no distance reward merely because both rows are null.

## Stage F — concentration/effective N

Report:

- raw neighbor N;
- issuer N;
- date-cluster N;
- theme/species concentration;
- same-parent episode dependence;
- effective N.

Consider diversity-constrained neighbour selection if one issuer/date dominates, but preregister it before outcome attachment.

## Stage G — freeze retrieval then attach outcomes

The neighbor set/order is frozen **before** MFE/MAE/R/success labels are joined for evaluation/reporting.

This is a crucial anti-hindsight receipt.

# 9. Counterexample-first law

A useful analogue system must fight confirmation bias.

Every product/research output should make it easy to inspect:

- nearest successful episode(s);
- nearest failed/false-bounce episode(s);
- same setup but different catalyst/theme;
- same catalyst but different price geometry;
- late/unavailable-entry cases;
- close-looking cases excluded for one critical mismatch;
- OOD reason when no genuine match exists.

Never sort the displayed analogue list by future winner status.

---

# 10. Empirical prior / probability law

A descriptive prior can eventually show:

- median/quantile MFE;
- median/quantile MAE;
- time-to-payoff distribution;
- false-bounce rate;
- threshold crossing probability with interval **only when effective N/calibration support it**.

Every statistic names:

- retrieval version;
- population/time range;
- effective N;
- concentration;
- prospective vs reconstructed composition;
- horizon/ruler;
- coverage/refusals.

If support is inadequate:

```text
prior_state = UNESTIMABLE
```

and show raw cases instead.

No `75% win rate` from six episodes.

---

# 11. OOD / no-match law

The system must explicitly detect when the nearest history is not actually close.

Research candidate tests:

- max/quantile distance support;
- feature-overlap minimum;
- density/support estimate;
- archetype/epoch incompatibility;
- required feature family absent historically;
- current state outside training-era range.

A forced nearest neighbor in an empty support region is misleading intelligence.
