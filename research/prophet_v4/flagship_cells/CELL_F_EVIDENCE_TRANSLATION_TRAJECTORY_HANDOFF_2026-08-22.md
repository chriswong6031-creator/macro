# 1. Why this cell is central to the flagship thesis

Mastermind already owns or is building many strong organs: Theme Graph, Earnings, Defense, BioCatalyst, Options, Capital Structure, FIF/Fundamental Forensics, Stock Identity, Market Memory, Radar, Dislocation and more. The failure mode is that each organ evolves its own terminology, confidence field, score, freshness rule and “bullish” interpretation.

If Prophet simply concatenates those outputs:

- correlated derivatives of one source masquerade as independent confluence;
- missing coverage looks like a weak signal;
- a domain lobe can accidentally outrank another through arbitrary scale;
- qualitative LLM output looks numerically comparable to deterministic facts;
- stale evidence survives because downstream consumers do not understand its clock;
- “more evidence” becomes a confirmation-count score that the architecture explicitly rejected.

Cell F solves the **translation problem**, not the prediction problem.

The moat is the governed history of how distinct evidence families change through time and which combinations later prove complementary—not a giant feature vector with no semantics.

# 3. Chairman intent — what “confluence” actually means

The Chairman wants Prophet to become more powerful as multiple independent kinds of intelligence agree. The dangerous simplification is:

```text
3 bullish lobes > 2 bullish lobes > 1 bullish lobe
```

That is not the intended system.

True confluence should ask:

- Are these pieces of evidence **actually independent**?
- Do they describe different causal/economic layers?
- Did they become knowable at different times?
- Is the second observation new information or a restatement of the first?
- Does the evidence apply to this issuer/species/episode?
- Is it still fresh?
- Is the family empirically useful for this context?
- Is the move already incorporated into price?
- Does fragility contradict the opportunity?

Therefore the contract must preserve evidence topology and provenance rather than merely output counts.

- decay/staleness;

Not every family gets every trajectory dimension. A clinical scheduled date does not have a meaningful generic “acceleration.” A capital-structure shelf may have persistence but not a continuous positive/negative slope.

## Layer C — Prophet intelligence heads

Potential orthogonal questions:

- **emergence** — is something meaningful beginning now?
- **theme/transmission** — is a contextual impulse relevant to this issuer?
- **catalyst/materiality** — is a discrete change unexpected/material?
- **incorporation gap** — does price appear behind the evidence?
- **empirical prior** — what happened in comparable episodes?
- **fragility** — what could make the thesis fail or impair path survival?
- **crowding/positioning** — is the trade already crowded/expensively expressed?
- **confidence/coverage** — how much of the intended evidence was actually observable?

These heads are not a single public score and do not need identical scales.

## Layer D — Fusion/ranking

Conditional Fusion may later learn how to use governed family/head features after promotion evidence. That is not D5's job.

# 6. Missingness / applicability law

A flagship vector fails if it turns absence into weak bearishness or zero.

The research must distinguish at least:

- `NOT_APPLICABLE` — family logically irrelevant;
- `NOT_COVERED` — intended source does not cover subject;
- `SOURCE_UNAVAILABLE`;
- `RIGHTS_BLOCKED`;
- `STALE`;
- `IDENTITY_UNRESOLVED`;
- `INSUFFICIENT_HISTORY`;
- `UNESTIMABLE`;
- `ACCRUING` — family declared but measurement/prospective clock not mature;
- `MEASURED_NEUTRAL` — real measurement says neutral/zero;
- `MEASURED` positive/negative/structured state.

The cell MUST reconcile these concepts with the actual existing D5/Fusion status vocabulary instead of creating a competing enum.

Coverage/confidence must be shown separately from evidence direction. “No options coverage” cannot make a candidate look less crowded.

# 7. Anti-double-count / evidence dependence architecture

This is a mandatory flagship feature.

The research must model that several observations can share one information ancestor.

Example:

- earnings transcript says AI demand strong;
- LLM summary says AI demand strong;
- theme-attention parser counts “AI” mentions;
- earnings sentiment becomes positive.

These are not four independent confirmations.

Design a dependence/lineage structure capable of expressing:

- exact same source document;
- same underlying economic fact propagated through several transforms;
- same provider/source family;
- same issuer event;
- genuinely independent first-party evidence;
- correlated market-derived features.

Potential structures to investigate:

- `lineage_group` / root evidence IDs;
- dependency DAG for evidence transformations;
- source-family correlation matrix learned later;
- deterministic dedupe for exact common ancestors;
- Fusion LOFO/ablation for empirical complementarity.

Hard rule: the D5 explainability layer may say “three observations from the same earnings event” but cannot call them “three independent confirmations.”

# 8. Trajectory semantics

“Trajectory” is useful only if it preserves domain meaning.

For each family the research must decide which are meaningful:

### Level
Current state relative to its own definitional scale.

### Delta
Change from the last comparable observation.

### Acceleration
Change in delta, only when the source cadence/scale supports it.

### Novelty
First appearance or statistically/semantically new information relative to a PIT baseline.

### Persistence
How long repeated compatible evidence has remained active.

### Decay
How quickly evidence should lose relevance if not refreshed.

### Revision / contradiction
Later information weakens/reverses a prior belief.

Mandatory edge cases:

- irregular event cadence;
- one-off events;
- revision restates history;
- source stops publishing;
- multiple observations within one market session;
- family moves from not-covered to covered;
- model version changes;
- source scale changes.

Do not genericize everything into z-scores. Preserve meaningful native units and use normalization only where the future consumer truly needs comparability.

# 9. Identity and candidate-episode joining

The source fact may be at company, security, theme, event, contract or macro level. Prophet ranks **candidate episodes**, not generic ticker facts.

The research must define when and how evidence attaches to an episode.

Rules to investigate/freeze:

- company-level facts route through canonical company/company-epoch identity;
- security-specific positioning remains security-specific;
- theme evidence attaches through the canonical GMI relation valid at that known time;
- event facts retain event identity and issuer mapping;
- evidence observed before episode creation may still be relevant if within family freshness law;
- evidence after the ranking snapshot cannot leak backward;
- a ticker rename/reuse cannot carry old issuer evidence into the new issuer.

The vector must remain reconstructible point-in-time for outcome replay.

## 10.1 Candidate emerges

A Radar/technical expert creates or updates a candidate episode through the canonical path. D5 does not invent the episode.

## 10.2 Evidence adapters resolve

Each owner adapter returns its governed evidence family state or a typed absence. D5 does not scrape the source independently.

## 10.3 Vector composes

The vector preserves:

- evidence direction/state;
- trajectory;
- applicability;
- coverage;
- freshness;
- dependence lineage;
- authority tier;
- receipt links.

## 10.4 Explainability assembles “why now”

The system can deterministically state something like:

> Customer capex evidence accelerated this week; the issuer has verified theme exposure; two independent customer sources agree; earnings evidence is stale; options crowding is unavailable because this security is outside current Theta coverage.

It must not invent a conclusion from missing evidence.

## 10.5 Availability remains separate

The candidate can be `ENTRY_OPEN`, `WAIT_PULLBACK`, `CHASED`, etc. according to deterministic availability. D5 cannot change this by adding positive intelligence.

## 10.6 Fusion consumes only lawful features

Later Fusion versions may rank using promoted fields. Unpromoted/model-generated context remains explanatory or shadow-only.

# 13. Evaluation and falsification

D5 semantics themselves need deterministic contract tests; family usefulness belongs to Eval/Fusion.

## Contract-level falsifiers

- future evidence appears in historical vector;
- same source duplicated into several “independent” confirmations;
- missing family becomes numeric zero;
- stale evidence remains fresh;
- correction rewrites old PIT history;
- ticker reuse leaks old issuer evidence;
- rights-blocked evidence reaches disallowed public surface;
- model-generated output lacks source span/receipt;
- vector changes deterministic entry availability;
- owner/source changes without version/lineage change.

## Utility-level research questions

- Does trajectory add value beyond level?
- Does dependence-aware confluence beat naive confirmation count?
- Which families are complementary vs redundant?
- Does confidence/coverage improve calibration/user trust?
- Do explanation primitives correspond to actual ranked features?

These questions feed Cell G / Fusion and remain outcome-blind until their lawful clocks permit reading outcomes.
