# 0. Purpose

The eight flagship research cells are **not eight implementation programs**.

They are research work packages that feed existing canonical owners and the already-frozen Prophet V4 integration graph.

This document freezes:

- where each research result is allowed to land;
- where it is forbidden to land;
- which existing workstream remains owner;
- what implementation gate must exist before mutation;
- which cross-cell dependencies are semantic vs executable;
- how to avoid converting a successful research fan-out into duplicate production planes.

The existing V4 `WAVE_GRAPH_AND_MERGE_ORDER.md` remains the execution roadmap. This document is an **overlay / routing contract**, not a second wave graph.

# 1. Freeze statement

## F1 — one candidate episode plane

Flagship intelligence attaches to the canonical Prophet candidate-episode grain once that V4 capability exists/adopts existing substrate. No cell may mint its own long-lived candidate lifecycle.

## F2 — one availability plane

`prophet.entry_availability/v1` or its accepted canonical successor remains the sole binding availability truth. Intelligence cannot independently derive green/actionability.

## F3 — one theme graph

GMI owns themes, company-theme exposure, typed economic relationships, ThemeState and transmission. Cell A is research for GMI/V4 D3-D4; no `flagship_theme_graph` is permitted.

## F4 — one cross-family ranker

Conditional Fusion remains the cross-family ranking arena. D5 translates evidence; E1 projects explainable priority; E3+ are challengers. Cell F/G cannot create another cross-family optimizer.

## F5 — one evaluation law

Eval OS / QLedger remain canonical for prospective claims, rulers, evidence clocks and promotion legality. Cell G extends experiments/scorecards over that substrate.

## F6 — one analogue memory owner

Market Memory owns reusable historical analogue memory. Cell D defines query/estimability requirements; no separate Prophet analogue store.

## F7 — specialist truth remains specialist-owned

Earnings, Bio, Defense, Capital Structure, Options, FIF/Forensics and future specialist lobes retain domain truth and methods. Prophet consumes adapters.

## F8 — one identity spine

Data OS exact identity remains canonical for security/issuer/listing truth. Stock Identity behavioral identity is a different research concept and cannot replace exact identity.

## F9 — research results do not grant authority

A research cell may complete with a recommended adapter/schema/algorithm. That does not authorize the owning V4 or specialist implementation wave.

## F10 — architecture can reject desired features

If a research hypothesis fails, the system preserves the architecture and drops/narrows the failed feature. We do not force every concept into production because it appears in the masterplan.

# 4. Cell A integration freeze

## 4.1 Exposure ownership

Any accepted company-theme economic exposure must live under GMI / canonical financial-segment truth, not in the Prophet adapter.

Prophet D5 reads an owner-produced exposure envelope.

### Legal future flow

```text
SEC/company/financial source
→ canonical segment/product fact owner
→ GMI company-theme exposure
→ GMI ThemeState/transmission
→ thin Prophet D5 evidence family
```

### Illegal flow

```text
LLM reads 10-K
→ Prophet writes ai_theme_exposure = 0.73
→ ranker consumes it
```

## 4.2 D3 / ThemeState seam

Cell A may propose ThemeState semantics now. Implementation belongs to GMI under the D3/W3B merge-order ruling.

If older Neural Web thematic-state code is reusable, D3 must explicitly `ADOPT`, `SUPERSEDE`, or `REJECT` each component. No silent duplicate state engine.

## 4.3 D4 / transmission seam

Cell A's mechanism ontology can become D4 only after:

- current identity/ontology gates satisfied;
- point-in-time edge validity is representable;
- ThemeState exists or D4 explicitly proves why it can operate independently;
- one mechanism has a real source→edge→consumer vertical.

Do not implement ten mechanisms in one PR.

## 4.4 Emergent-theme seam

Emergent-theme discovery is a **proposal/ratification workflow inside GMI ontology governance**, not a Prophet family that autonomously mints themes.

- how was it derived?

# 20. The D5 contract can precede data — but values cannot

This is a critical sequencing rule.

It is valid to define:

```text
family = theme_state
status = ACCRUING
value = null
null_reason = canonical_theme_state_not_available
```

It is not valid to fill that field from an older convenient predecessor merely to avoid a null.

Definitions-before-data is intentional.

# 21. The deterministic E1 baseline must exist before learned complexity

Before E3/E4/E5 can claim incremental value, E1 must provide a strong explainable baseline.

Why:

- exposes whether fancy models solve a real problem;
- allows LOFO/ablation;
- provides fallback behavior;
- makes feature semantics reviewable;
- reduces overfitting;
- gives the product a useful system before learned authority matures.

No cell should advocate skipping E1 because a neural architecture looks more powerful.

# 23. Promotion / demotion integration

Feature authority belongs to frozen feature versions.

A promoted feature must be demotable when:

- coverage changes materially;
- source semantics change;
- model version changes;
- identity mapping changes;
- calibration degrades;
- lead time worsens;
- regime/species concentration invalidates broad scope;
- correction replay reveals leakage.

The product must continue to display downgraded evidence honestly if it remains useful context.

# 24. Integration failure modes

## IF-1 — “successful cell becomes new service”

A cell returns a useful design and a builder creates a new service/store rather than extending the owner.

**Response:** HOLD. Map producer/consumer and adopt owner first.

## IF-2 — “all research outputs become D5 fields”

Interesting but unestimable ideas fill the intelligence vector.

**Response:** keep null/context/rejected state; no decorative fields.

## IF-3 — “D5 becomes the ranker”

Translation code starts assigning cross-family weights.

**Response:** HOLD; Conditional Fusion owner breach.

## IF-4 — “risk becomes veto”

Fragility adapter silently blocks ENTRY_OPEN.

**Response:** BLOCKER; availability firewall violation.

## IF-5 — “product invents field”

H mockup requires “Theme Confidence 87” and upstream has no such contract.

**Response:** remove/replace with lawful state; do not retrofit fake semantics.

## IF-6 — “backtest creates evidence clock”

A new feature is run on old episodes and treated as prospective N.

**Response:** historical research only; start a new forward clock.

## IF-7 — “analogue memory fork”

D creates a vector DB because Market Memory API is not ready.

**Response:** interface requirement + bounded temporary research artifact only; no durable parallel store.

## IF-8 — “theme graph fork”

A creates local graph because GMI workstream record looks stale.

**Response:** owner record still owns graph; stale status does not transfer authority.
