## Regime-change summary for 2024→2026 (so signals don't assume dead feeds)

1. **Northbound (北向/沪深港通 into mainland) daily net-flow: dead**, confirmed at the field level (see Family 2 box) — killed in two steps: realtime intraday flow cut 2024-05-13, then daily aggregate/net-flow disclosure moved to **quarterly** (5th trading day of each quarter, per-security holdings only) starting 2024-08-19. What EastMoney's mirror still returns for northbound legs is a hard `0.0`.
2. **Southbound (港股通, mainland into HK) daily net-flow: still alive**, confirmed with real non-zero numbers on 2026-07-24 via the same `RPT_MUTUAL_QUOTA` report — not affected by the northbound disclosure rule change. This is the more usable of the two for a China-signal platform going forward.
3. **转融券 (securities re-lending) is still suspended**, confirmed via WebSearch: suspended 2024-07-11, balance zeroed by 2024-10-01, and as of this search (2026-07) no restart has been announced. Any factor keyed to 转融券 balance changes is measuring literal zero and should be treated as structurally dead, not "quiet."
4. **Program-trading reporting rules are now fully in force**: CSRC provisional rules effective 2024-10-08; the three exchanges' implementation rules effective 2024-07-07(2025). This is a **compliance/reporting regime** (institutions report their program-trading identity to exchanges) — it does **not** create a new public data feed for us to consume; it's regime color (may explain some liquidity/microstructure shifts), not a new source.
5. **ChinaClear's headline investor-count series is confirmed alive but annual-cadence**, not the monthly series some older references imply — see Family 6.

## Method notes / honesty caveats

- "Rate limits" cells are marked "unpublished" throughout — no endpoint in this catalog documents a formal rate limit, and this pass did **not** hammer any endpoint repeatedly to empirically find one (that would risk tripping a ban on infrastructure we want to keep using). Treat all rate-limit guidance as **UNVERIFIED / community-norm** until we have production telemetry.
- A handful of rows are marked **UNVERIFIED** or **PARTIALLY VERIFIED** explicitly in-cell (LPR, direct chinabond.com.cn, fund NAV exact params, GFEX non-empty payload, CSI full-export POST) — these are exactly the ones where either (a) I found the akshare wrapper exists but did not myself confirm a working param set live, or (b) the transport worked but I could not confirm real (non-empty) data in the time available. Do not treat these as ready to integrate without one more verification pass.
- Every other row was called **live from this machine** during this session with an actual HTTP status, byte count, and (for JSON) a parsed-field sanity check — not inferred from documentation or akshare docstrings alone.
