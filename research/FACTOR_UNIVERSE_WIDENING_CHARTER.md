#4688 widened the **fundamentals** universe (EDGAR panel 1,552 → 2,826 tickers) by unioning
each breadth group's committed `constituents.parquet` with its closes cache. It moved
`heal_candidates_archetype` on `2026-07` from 1,457 still-absent to 835.

It deliberately did **not** widen the **price** universe. `engine/equity_factors.py:313`:

```python
_UNIVERSE_GROUPS = {"broad": ("breadth", "smallcap_breadth", "midcap_breadth"),
                    "narrow": ("breadth",)}
```

`russell_breadth` is absent, so a Russell-2000-only name gets no price → no mktcap → no
factor row → `fac_present=False` → no archetype label. **1,278 of the 1,316 tickers that
never receive a factor row in any fiscal year are Russell-only.** The archetype store
labels 100% of rows carrying a factor row (22,070/22,070) but only 46% of `fac_present=False`
rows (6,349/13,883), because the fac-less `_archetype` path honestly withholds a label
rather than fabricating `mixed`.

Adding one string to that tuple looks like the fix. It is not, for three separable reasons,
each measured below:

- every factor leg is a **winsorized cross-sectional z**, so the population *is* the
  yardstick (§3, §4);
- `composite_rank` is a **board tiebreak**, i.e. rank authority, not display tier (§6);
- the Russell closes cache is **gitignored** and absent in CI packs and on cold clones, so
  a naive widening produces different rankings per host (§7).

## §3 What a POOLED widening costs — measured

Reproduce: `python3 scripts/factor_universe_widening_phase0.py --stage churn`

Pooled = the naive fix: add `russell_breadth` to the `broad` group and let one cross-section
define μ/σ for everyone.

```
A (S&P 1500)      n=1354
B (+R2000-only)   n=2400   (+1046, +77.3%)

leg                 sd A    sd B  Spearman   <- within the SAME 1,354 names
value              0.927   0.439   0.66326
quality            0.927   0.758   0.75753

payout             0.906   0.841   1.00000
low_vol            0.995   0.674   1.00000
composite          0.444   0.279   0.70331
```

The Spearman column is computed **within the names that were already on the page**. It is

What a user sees:

```

```

Per-leg top-20 leaderboards fare worse: value retains 1/20, quality 1/20, investment 3/20.

**Three-quarters of the names on `site/factors.html` change decile, and the composite
top-10 loses eight of ten.** That is not a re-percentile. It is a different ranking.

## §4 The mechanism — and why it is worth naming

The four legs with Spearman ≈ 1.000 (`profitability`, `payout`, `low_vol`, `investment`)
are each a **single** winsorized ratio. A z is monotone in its input, so within a fixed
input the ordering cannot change — only the scale does.

The two legs that reorder (`value` 0.663, `quality` 0.758) are each a **mean of several
separately-winsorized z's** — value averages ey/bp/sp/cfoy, quality averages roe/−accruals/−leverage.
`_winsor_z` clips at ±3σ **after** computing μ/σ on the raw ratio, so when the population
changes, the clip point moves *by a different amount on each sub-leg*, and the mean of the
clipped z's reorders. The composite inherits it.

The R2000 raw ratios are extraordinarily fat-tailed relative to the incumbents
(`--stage frozen` prints these): book/price sd **11,319** vs 0.469; earnings yield sd
**1,190** vs 0.204; ROE sd **606** vs 0.938. Pooling imports those tails into μ/σ, which is
exactly why incumbent `value` sd collapses 0.927 → 0.439 and `investment` 0.895 → 0.113 —
the incumbents are squeezed into the middle of a distribution defined by microcap outliers,
the ±3σ clip stops binding where it used to, and the mean-of-sub-legs re-sorts.

This is mechanism #4 of the blue-chip audit (`[[single-tag-xbrl-and-fillna-zero-poison-factor-legs]]`,
"winsorize-the-z ≠ winsorize-the-ratio") operating at population scale rather than at
single-name scale. **A pooled widening does not merely dilute the ranking — it hands the
yardstick to the fattest tail in the room.**

## §5 Equal-N decomposition — direction, not count

`[[universe-widening-rebase-is-cohort-direction-not-count]]` requires this before costing a
universe change: remove k by the ordering the expansion would follow, versus k at random.

Reproduce: `python3 scripts/factor_universe_widening_phase0.py --stage equaln`

```
removing k=1046 from n=2400
(a) CAP-ORDERED  shift -0.0256  Spearman 0.7784  top-50 Jaccard 0.196
(b) RANDOM x20   shift -0.0259  Spearman 0.9740  top-50 Jaccard 0.495

ordering loss (1-Spearman): cap-ordered 0.2216 vs random 0.0260  -> 8.5x at IDENTICAL N
```

**This refines the law rather than merely confirming it.** In the China case the cohort
signature was a one-directional shift in the *median level*. Here the median level shift is
identical in both arms (−0.0256 vs −0.0259) — the level channel is **not** the tell. The
cohort signature lands entirely in **dispersion and ordering**: at identical N, size-ordered
removal destroys **8.5×** more rank information and retains less than half the top-50.

So: for a winsorized-mean composite, run the equal-N decomposition on **Spearman and
Jaccard**, not on the median shift. A median-shift-only reading of this widening would have
returned "cohort direction is not the channel, ship it" — and been wrong.

Secondary finding worth its own line: the **random** arm still moves top-50 Jaccard to
0.495. Dropping 44% of the cross-section at random churns half the composite's top-50. The
composite's leaderboard is a fragile object with respect to its population *independently of
this widening* — which is an argument for stabilising it before growing it, not after.

## §6 The authority question

CLAUDE.md epistemics: *"context/data/detection/tagging infrastructure ships display-tier
freely — a null NEVER blocks building or accrual; the gauntlet applies only when promoting
to authority (rank/size/gate)."*

The factor composite is already **past** that line. `scripts/build_stock_library.py:2188`
and `scripts/build_site.py:3797`, in the same words:

> *audit #25: the board TIEBREAK must use the scorecard-passing IC-weighted composite
> (`composite_rank`), NOT the blind equal-weight composite (ic_ir −0.049, anti-predictive).*

`composite_rank` → `factor_z` → the standout board ordering. That is **rank authority**.
It is also read by `engine/neuralweb/brain_gateway.py:2538`, so it reaches the Mastermind
chat surface.

Therefore the widening is **not** a display-tier data top-up that ships freely. It changes
the population that defines an authority-bearing quantity, and the incumbent IC scorecard
(`data/edgar/ic_scorecard.json`) — which gates which legs enter `composite_rank` at all —
was measured on the *narrow* population. After a pooled widening, every scorecard weight is
being applied to z's that no longer mean what they meant when the weights were fitted.

**Ruling:** a pooled widening is a **promotion-tier change** requiring pre-registration and
the gauntlet (§11). It is not blocked as a *build*; it is blocked as a *ship to the ranked
surface*. Accrual, measurement, and display-tier consumption of R2000 factor rows remain
free — which is precisely what Option D exploits.

It is restored by `actions/cache` with `restore-keys: russell-closes-` in `daily.yml:104`
and `closing-bell.yml:207` — **and nowhere in `ci.yml`**. So it is absent in every CI pack,
absent on every cold clone, and present on a self-hosted runner only if the 7-day cache has
not evicted. A factor build reading it produces **different rankings per host**.

This is not hypothetical. `scripts/build_stock_library.py:686` already reads that cache and
already carries the postmortem in a comment:

> *A missing source group silently shrinks the emitted universe by O(1000) names, and the
> downstream name-score ledger stamp is keep-FIRST PIT — the hole is permanent (2026-07-25:
> the weekly lane, which restored no russell cache, stamped 1,704 US names between
> 2,966-name nightly stamps).*

**The same hazard, in the same file, has already fired once and left a permanent hole in a
PIT ledger.** The factor path would be the second consumer.

**Resolution (required, ships alone, gate §0.1):** delete `.gitignore:80` and track the
cache like its three siblings. Cost is ~7 MB/day of nightly churn on top of the 22.5 MB/day
this directory already commits in high/low/volume — a +31% marginal increase on a cost
already being paid, in exchange for removing a per-host non-determinism from a ranked
surface. The asymmetry is the bug: the repo commits the three price series nothing reads
and ignores the one everything reads.

Rejected alternative: **deriving** closes from the committed high/low midpoint. The harness
validates that proxy every run — last-price Spearman 0.9999, |err| p50 0.67% — but the
**volatility** Spearman is only 0.858 and the midpoint understates annualised vol by ~12%
(it smooths intraday range). `low_vol` is a shipped leg. A derived close is fine as a
measurement device and unfit as a data plane.

Defense in depth: whichever option ships, the consumer must **abstain loudly** (a
line-start `::warning`) and keep the narrow universe when the cache is absent, rather than
silently ranking a shrunken panel.

## §8 Constraint: are the legs meaningful on R2000 microcaps?

Reproduce: `python3 scripts/factor_universe_widening_phase0.py --stage coverage`

One keyless SEC frames call per concept returns every filer, so this is a census, not a
sample: 1,518 S&P-1500 CIKs vs 1,310 Russell-only CIKs, FY2024.

| leg | concept | S&P 1500 | R2000-only |
|---|---|---|---|
| assets | `Assets` | 99.4% | 96.0% |
| cfo | `NetCashProvidedByUsedInOperatingActivities` | 97.2% | 95.1% |
| ni | `NetIncomeLoss` | 95.8% | 93.7% |
| equity | `StockholdersEquity` | 95.3% | 93.3% |
| op_income | `OperatingIncomeLoss` | 76.9% | 75.7% |
| gross_profit | `GrossProfit` | 42.1% | 36.3% |
| debt_lt | `LongTermDebtNoncurrent` | 49.3% | 34.8% |
| repurchases | `PaymentsForRepurchaseOfCommonStock` | 77.1% | **41.1%** |
| dividends | `PaymentsOfDividendsCommonStock` | 40.3% | **17.4%** |
| interest_exp | `InterestExpense` | 26.0% | 15.9% |

**The intuition that "filings coverage thins out at small caps" is mostly wrong, and it
matters.** The balance-sheet spine and the core flows reach the Russell at 93–96% — within
2–4 points of the S&P 1500. At the leg level (`--stage frozen`), R2000-only names score
`value` 98.3%, `investment` 98.2%, `quality` 96.8%, and **98.3% clear the ≥3-leg bar** the
composite requires. Coverage is **not** the blocker. §3 is the blocker.

Two real exceptions, both already-known defects rather than new ones:

- **`payout` halves** (86.6% → 49.4% at the leg level). Names with *neither* tag correctly
  go NaN, but names with exactly one tag get `fillna(0)` for the missing half — the
  `[[single-tag-xbrl-and-fillna-zero-poison-factor-legs]]` trap. The poisoned share is
  **53.2% of the S&P 1500** and **36.8% of R2000-only** names. The incumbent surface is
  *more* poisoned than the cohort being added.
- **`profitability` is thin everywhere** (42.1% / 36.3%) because `GrossProfit` is a
  minority tag. Not a size effect.

So the honest reading: widening does not import a coverage hole. It imports a **fat-tailed
population into a yardstick that is already carrying a known input defect** — which is why
§9.1 sequences #4685 first.

Option D estimates μ/σ on the incumbent S&P 1500 cohort **only** and applies that frozen
yardstick to Russell names. Consequences:

- **Incumbent z's are bit-identical.** No re-percentile, no era break, no falsified copy,
  no scorecard invalidation, no board-tiebreak change. §3 does not apply.
- **~1,028 R2000 names become archetype-labelable** — the actual consumer need, delivered
  in full.
- **The yardstick keeps one meaning.** `_archetype` gates on *absolute* z thresholds
  (`quality ≥ 0.5`, `payout ≥ 0.5`, `value ≥ 0.75`), so a shared reference is required for
  the label to mean the same thing across cohorts. This is the decisive advantage over
  Option B, whose within-stratum z would silently redefine every gate for small caps.
- All three sampled gates stay reachable (30.1% / 9.1% / 21.5%), so labels will not
  degenerate into one bucket.
- **The R2000 tail gets compressed and this must be disclosed.** Clip rates run 4.8–14.2%
  vs 0.4–2.3% for incumbents; `investment` and `low_vol` pin at the ±3 cap for ~13–14% of
  Russell names. That is *honest* — a microcap genuinely sits outside the large-cap vol
  distribution — but it means within-R2000 ordering is lossy in those two legs, and R2000
  rows must carry that caveat.

**Required shape of the Option D implementation:**

1. New column `universe_tier ∈ {sp1500, russell}` on every factor row.
2. R2000 rows are **excluded** from `site/factors.html` tables, leaderboards and the
   universe switch, and **excluded** from `composite_rank`/`factor_z` (the board tiebreak),
   until and unless §11 is ratified. The measured top-20 flooding in §3 is the reason:
   16 of 20 value leaders would become Russell names overnight.
3. R2000 rows are consumed by the archetype/Atlas path only, carrying `fac_present=True`
   plus a `reference_frozen=True` flag so cohort QA can separate them.
4. The frozen reference is **stamped, not recomputed per call**, so an incumbent-cohort
   change is itself a visible event.

## §11 Pre-registration required for Option C (pooled)

If the operator prefers the pooled construction, it is a promotion-tier change and needs,
frozen **before** any number is looked at:

1. **Primary gate.** Re-run `data/edgar/ic_scorecard.json` on the widened population, with
   BH-FDR across legs. The rank-facing composite may keep authority only if the
   scorecard-passing leg set and its IC signs are stable versus the narrow population. A
   leg that flips sign is a **kill for that leg's authority**, not a re-weight.
2. **Era break, declared.** Stamp the widening date on `data/edgar/` artifacts and the
   forward ledgers keyed to factor z's; pre- and post- rows are not comparable and must not
   be pooled in any grading.
3. **Pre-stated churn tolerance.** Publish the acceptable decile-change rate *before*
   measuring. The measured 74.7% must be judged against a number written down first.
4. **Both equal-N arms reported** (§5) — Spearman and Jaccard, not median shift.
5. **Nulls printed.** If the widened scorecard grades the composite anti-predictive (the
   narrow one already reads `ic_ir −0.049`), that null ships to the surface; it does not
   become a reason to keep the narrow universe quietly.
6. **Copy re-read** per §9.3 in both languages.

Absent a ratified pre-registration, Option C is **held** — see the registry row.

## §12 Reproduction and limits

```bash
python3 scripts/factor_universe_widening_phase0.py --stage all
```

Deterministic apart from the SEC fetch (seed 20260806, no wall-clock). Frames cache to a
tmp dir, never into `data/`.

Honest limits on every number above:

- **One cross-section** (FY2024 frames, current prices). This is a *cost* measurement of a
  construction change, not a forward or alpha claim. Nothing here says the widened ranking
  is better or worse at predicting returns — only that it is a **different** ranking.
- **Russell prices are the committed high/low midpoint**, because the real closes cache is
  the gitignored artifact this charter is about. The proxy is validated on the S&P 1500
  cohort every run (last-price Spearman 0.9999, |err| p50 0.67%); the **vol** leg is the
  weak spot (Spearman 0.858, ~12% understated), so `low_vol` reads in §3 and §10 are
  indicative. Value/quality/payout/investment conclusions do not depend on it.
- **n=1,354 not 1,515** for the incumbent arm: the harness requires both a CIK map and a
  DEI share count from the same FY, which the engine backfills from other sources. The
  comparison is like-for-like across arms, so the churn ratios hold; the absolute count is
  a floor.
- **`_reconcile_shares` is not applied** (it is a live-path S&P-500-only override). BKNG-class
  split staleness is therefore present in both arms equally.
- The §5 per-leg direction table in the harness uses 6 random draws and is indicative; the
  composite figures use 20 and are the citable ones.
