## §2 Identity architecture

- Join key today is the normalized bare ticker everywhere in private state (`normalizeTicker`); options alerts already carry the richer canonical identity (`canonicalizeOptAlertIdentity` — persisted symbol derived from `condition.root`; market-wide → `MARKET`). **Freeze:** F08 composes on normalized ticker and treats macro Security Identity (`security_state.v1` / stock dossier at R2 `/stockdata/<TICKER>.json`, MO-PAID-020 owner) as the enrichment join — never a second identity registry.
- **Partial-identity state is a first-class display state:** a holding whose ticker fails to resolve in the identity/price join is EXCLUDED from aggregates and COUNTED in the excluded denominator with a per-row "identity unresolved" chip — never silently dropped, never zero-valued. Identity conflict (two sources disagree on the instrument) → degrade the affected aggregate, name the conflict.

## §3 Time architecture

- Adopt `engine/alert_time.py` three clocks cross-product: `event_time` (when the market fact occurred), `source_asof` (data vintage), `recorded_at` (when we wrote it). Every alert row, run receipt, and aggregate carries all three; board dating uses `board_date()` NY projection. User-facing schedule semantics (quiet hours, digests) use the user's own timezone pref (§8), never the NY board projection.
- **Freshness is displayed, not implied:** every panel states its `source_asof`; a quote/holding older than its lane's freshness budget renders the stale state (§5), not the calm state.

## §4 Run-receipt law (last-attempt vs last-success — the core new invariant)

Evidenced gaps this law closes: `build_bonds.py:1433-1440` fallback renders yesterday's alert state as current; `alerts_engine.py` persists no record that a cron ran (`done:` stdout only); `watchlist_alerts.py` cannot distinguish never-ran from ran-empty; suite sidecar likewise.

- Every evaluator run and every delivery attempt writes a durable receipt: `{lane, run_id, started_at, concluded_at, outcome ∈ {success, partial, failure}, evaluated_n, fired_n, unevaluable_n, source_asof, lane_cadence_budget, error_class?}`.
- **Receipts are two-phase:** a `started` row at run open, the terminal row only after the lane's output is durably committed. `outcome` is DERIVED from the lane's typed reads (§5 vocabulary), never asserted; **any fallback to previously persisted state forces `outcome=partial` AND re-stamps the served artifact's `source_asof` to the fallback vintage** — this is the clause that actually closes the `build_bonds` defect.
- **Named sinks per lane:** Terminal-side a small `alert_runs` table (or equivalent existing-owner store per gate ruling); macro **nightly** lanes a jsonl under the lane's `data/<domain>/` (nightly is the sole forward-ledger advancer). Macro **intraday** lanes discard `data/` writes by repo law (closing-bell FT-R5), so an intraday receipt path must EITHER be added to that workflow's commit whitelist under an operator/DEC record, OR the lane is declared unreceipted and its surfaces may not claim intraday freshness — silently degrading calm-proof to nightly resolution while implying per-run proof is forbidden.
- **Calm requires proof-of-run:** a surface may render "clear/current" only when the newest receipt for its lane is `success` within `lane_cadence_budget`; otherwise it renders "monitoring degraded — last successful check <t>". `last_attempt` and `last_success` are separate displayed facts on every monitoring surface and each alert row. (This is the Sol calm-law: calm is lawful only when the latest evaluation ATTEMPT succeeded.)

## §5 Null / denominator / degradation / privacy boundary

- Every book aggregate: `total`/`included`/`excluded` counts + per-basis split (live / fallback / missing). Missing price, identity, or risk input is **not zero** — the row is excluded and counted. Dominant material degradation propagates to panel state (macro degradation law).
- **Duplicate-row law (Mastermind redline):** `portfolio_positions` legally holds multiple rows per ticker (no natural-key constraint). Every F08 book read folds rows to position identity `(user_id, normalized_ticker, status)` before aggregating; `positions` and `rows` are separate displayed counts, with a "duplicate rows folded (n)" disclosure whenever n>0. An aggregate computed over unfolded rows is a defect even when the denominator is honest.
- **Read vocabulary (frozen, four states):** the macro typed-read set `READ_OK / READ_OK_ZERO / READ_NO_COVERAGE / READ_UNAVAILABLE` is canonical for every F08 read. HTTP mapping: 401 → signed-out; 200-empty → `READ_OK_ZERO` (calm-empty); 503 → `READ_UNAVAILABLE` (outage); a resolvable book whose instrument lacks coverage (foreign/OTC/unpriced) → `READ_NO_COVERAGE`, rendered "not covered", never calm and never outage.
- Mixed live/cost basis is a Mastermind redline: an aggregate never sums across bases without declaring the split.
- **Attention truth is read ONLY from `terminal/app/api/watchlist/route.ts`;** the `mm.wls` client cache (known prior cross-user-leak surface) is never a read source for any F08 surface.
- **Privacy boundary (invariant):** no user identifier, holding, alert condition, or any user-scoped field may be written to `site/`, `data/`, R2, or any triage feed (`alerts_triage.json`, `feed.json`) — these are published/shared artifacts with neither RLS nor owner scoping. User-plane delivery executes in a module with no `site/` write path. CI-checkable; §11 hostile test asserts the public feeds contain no user-scoped fields.

## §6 Dedup / replay / idempotency freeze *(reconciled against the current `alerts_engine.py` body — see header)*

- **User-alert fire idempotency:** the `active=eq.true` guarded PATCH is THE mechanism — one-shot disarm + `condition.triggered` stamp; re-arm is a user act that strips the stamp. Every fire mints a durable `fire_event_id`.
- **Fire→delivery outbox (closes the lost-alert hole):** the fire transaction durably records the delivery intent — an outbox row keyed by `fire_event_id` — before or atomically with the disarm. Retry drains the outbox, never re-evaluation; a fire with no terminal delivery state renders `pending`, never calm, and is thereby distinguishable from delivered.
- **Event identity:** macro jsonl lineage's engine-minted stable id (append + dedup-by-id, keep-first) is the frozen pattern for new event streams; no cross-engine shared namespace is created — composition happens at read time via `(lane, id)`.
- **Delivery replay protection, two planes:** OPERATOR plane keeps `push_sent.jsonl` + same-`(source,type,asset)` 6h silence window, frozen as-is — and stays exclusively operator (ops-liveness dispatch-always invariant preserved; user sends never enter `push_sent*.jsonl`, so they can never silence an ops alert or each other). USER plane dedup is keyed `(user_id, alert_id, fire_event_id)` with `fire_event_id` as the idempotency key in a user-plane store; for email that store IS `email_log` and the idempotency gate IS its UNIQUE `idem_key`, derived deterministically from `fire_event_id` — no new email ledger is created.
- **Duplicate/replayed input events** (same id re-seen) are no-ops by construction; a REPLAYED run (same run over the same vintage) may not re-fire user alerts (guard) nor re-send (outbox key + `idem_key`).

Holdings corrections flow through the existing A1A route semantics (update/close/reopen), never bulk rewrites.

- **Send-time entitlement re-check is fail-closed and is a V4 acceptance gate:** a lapsed subscriber's paid-tier conditions stop evaluating-to-send BEFORE any channel goes live (not deferred to V5).
