## Marketing Chart Rendering — Inventory Report

### 1. RENDER STACK

- **No matplotlib.** `engine/marketing/chart_render.py:1-30` — pure-Python, hand-built SVG string templates (no charting library dependency beyond pandas/pyarrow for parquet reads). ~3,666 lines, five renderer families in one module.
- **Rasterization:** SVG → PNG via **headless Chrome** (`chart_render.py:83-118, find_chrome/rasterize_svg`), matching `scripts/make_favicon.py`. Fail-soft: no Chrome → `b""`, caller falls back to a legacy PIL renderer (`render_signal_chart_png`, `chart_render.py:682`). 2x device-pixel-ratio (retina) raster of the exact posted SVG (comment at `chart_render.py:44-66` explains a 2026-07-26 incident where a separate PIL reimplementation drifted from the SVG preview — now eliminated).
- **Theme:** dark-navy `#0E1420` background (`chart_render.py:732, 2267`), panel dividers `#232A3D` (`2026`), up `#4CAF50` / down `#E23B3B`. Default canvas `render_chart_v2` 1000×850 (`1420-1421`), but every live call site overrides `height=880` (content_studio, weekend_levels). `render_watchlist_card` defaults 1080×1350 portrait (`2836-2837`); `render_earnings_card` 1000×610 (`2415-2416`); `render_breaking_card` 1000×560 (`3355-3356`).
- **House style knobs are NOT externalized to a YAML.** No house-style config file exists — colors/fonts/dims/layout constants are hardcoded Python literals inside `chart_render.py` (confirmed: no `yaml`/`open(...yml)`/`config/marketing` reference anywhere in the file). The only config-driven render knob is `publish.chart_cta_enabled` (`config/marketing.yml:510`, read by `chart_cta_enabled()` at `chart_render.py:1229-1250`) and `marketing.m2_overlays_always` (read ad hoc in `content_studio.py:2986-2988, 3253-3255`, not present as an explicit key in `config/marketing.yml` so it defaults `True`/`False` per call site — inconsistent default between the "signal" lane (`True`) and the "confluence" lane (`False`)). `config/personas/chart_gremlin.yml` is a **planned, unwired persona voice spec** ("SPEC ONLY: no desk_network entry... nothing generates from this file", line 3) — not a rendering config.
- **Invocation chain (daemon):** `scripts/build_marketing.py:main()` → `engine.neuralweb.marketing_governor.build_and_write()` (`marketing_governor.py:115-176`) → `engine.marketing.content_studio.content_plan()` (renders SVGs inline or deferred) → `content_studio.raster_plan_media()` (`content_studio.py:2388-2460`, PNGs only survivors, ~13s/Chrome launch) → `outbox.emit_from_content_plan()`. No launchd plist found scheduling `build_marketing.py` in this worktree (likely external to repo/ops dir scanned).

### 4. ANNOTATION VOCAB

Primitives that exist and how a post lane invokes them (all via `render_chart_v2` kwargs, `chart_render.py:1399-1426`):
- `marker_index` / `highlight_index` → BUY-style highlight disc + downward arrow + "SETUP" pill (`1954-2007`); suppressed together when both `None` (tape/watching posts, comment at `content_studio.py:2997-2999`).
- `pct_from_index` → % change callout box, gated `bars_elapsed>=5` and `|Δ|>=3%` (`_CALLOUT_MIN_PCT`, `1026`); "since setup" return chip (`1914-1953`).
- `level_overlay: {"price": float, "label": str}` → one dashed horizontal line + label chip — the mechanism enforcing the "text may only name a level the chart draws" law (`chart_render.py:1447-1451`, `weekend_levels.py:667-670`).
- `avwap_overlay` / `poc_overlay` dicts → curve + POC dashed line + value-area band, with right-edge label chips using a **de-conflicting reserved-lane system** shared across M2 labels and SMA end-labels (`1691-1730`).
- SMA end-label chips (`"50 SMA"`, `"200 SMA"`) — inline, same-color as the line (`1888-1921`).
- Ghost watermark / giant monochrome logo (TrendSpider-signature move) (`2008-2020`, logo whitening `1109-1226`).
- No arrow/callout **leader lines to arbitrary points**, no free-text annotation API — the only text a post lane can inject onto the chart is the single `level_overlay.label` string and the ticker/company name; everything else is baked into the renderer's own copy (SETUP, since-setup, % callout, axis labels).
- Public-copy law (`config/marketing.yml:1394`): copy may never *name* MACD/RSI/Stochastic/Ichimoku/Bollinger/VWAP/AVWAP/POC/value-area, but **visible chart SVG labels for these are explicitly fine** — i.e., the annotation vocab is allowed to be richer than the copy vocab, a headroom the renderer doesn't currently use (no Bollinger/Ichimoku/Stochastic labels exist to show).

### 5. TIMEFRAMES

- **Daily bars only, in every live call.** `timeframe="DAILY"` is passed as a literal string at every call site found (`content_studio.py` x4, `weekend_levels.py:661`, `publish_time_content.py`, `hot_tape_radar.py`, `dev_render_m2_sample.py`); grep for `"WEEKLY"` passed to `render_chart_v2` or `timeframe=` returns zero hits. The `timeframe` kwarg is a cosmetic header label, not a resampling instruction.
- **Lookback window is small and fixed:** `MKT_VIS, MKT_WARM = 90, 60` (`chart_render.py:989`) — `load_ohlcv_windowed()` (`992-1026`) requests **150 daily bars max** (90 visible + 60 warm-up for SMA50/MACD warmup), `load_ohlcv`/`load_closes` default `n=90` (`903-906, 374-377`).
- **Data source:** `_PRICE_SUBDIRS = ("data/baskets/ohlcv", "data/stocks")` (`chart_render.py:253`), i.e. `data/baskets/ohlcv/<TICKER>.parquet` (2,758 names, real OHLCV) then `data/stocks/<TICKER>.parquet` (232 large caps) as fallback; crypto falls back to `data/yahoo/<TICKER>-USD.parquet` (close+volume only, synthesized high/low, `914-918`). Hot Tape radar opts into an extra `data/massive_stock_day` tier (`265-278`, deliberately excluded from the default order — not split-adjusted, can be stale).
- **Depth actually available:** sampled parquets go back to 2014 (e.g. `data/baskets/ohlcv/GFI.parquet`: 3,163 rows, 2014-01-02 → 2026-07-31; `SGRY.parquet`: 2,724 rows since 2015-09-30), i.e. **10-12+ years of daily bars are already sitting in the same parquet trees the renderer reads** — nothing prevents drawing a 5-year weekly chart on data depth grounds. The gap is purely on the render side: no weekly resample step exists in `chart_render.py`/`content_studio.py` (contrast with `engine/neuralweb/chart_perception.py:547-594`, which *does* resample weekly for the chat digest, and `engine/tech_confluence.py`'s "W" signal families, which resample weekly for signal mining — neither path feeds the marketing chart).

### 6. THE CHART SPEC CONTRACT

There is **no dataclass/pydantic/JSON-schema contract** — the contract is the keyword-argument surface of `render_chart_v2()` itself (`chart_render.py:1399-1426`): `ticker, dates, o, h, l, c, volume, *, timeframe, marker_index, highlight_index, pct_from_index, show_indicators, indicators, warmup, volume_overlay, subpanel_h, company_name, logo_datauri, logo_root, width, height, footer_cta, cta, avwap_overlay, poc_overlay, level_overlay`. Every post lane builds these kwargs inline ad hoc (duplicated per lane rather than shared through a builder function) — see near-identical but drifting blocks at `content_studio.py:3001-3040` (signal), `3288-3315` (confluence, dynamically gates M2 overlays on fired leg families), `3759-3779` (mover), `4074-4082` (filing/house-picks), `weekend_levels.py:653-673` (level-cited), `publish_time_content.py:912-919`, `brain_gateway.py:3313-3318`, `hot_tape_radar.py:1268-…`, `scripts/dev_render_m2_sample.py:63-…`.

Downstream of rendering, the plan-level artifact schema is a `featured_charts` dict built per call site, e.g. `content_studio.py:3070-3081`: `{"id": chart_id, "ticker", "account", "cashtag", "variant", "marker_source", "marker_date", "marker_price", "svg", "headline", "body"}`, later mutated with `media_png_path`/`media_url`/`media_render` by `raster_plan_media()` (`2388-2460`) or carrying a `"_defer"` sub-dict of raster inputs (`3096-3102`) when rastering is postponed until after the Sentinel gate.

The parallel **copy-facing contract** is `engine.marketing.chart_facts.compute_facts(ticker, dates, o,h,l,c,v)` (`chart_facts.py:995-1112`) → `{"facts": [{"id","text","salience","numbers"}], "numbers_whitelist": [...]}`, computing pct-change (5/20/65-bar), 52w high/low proximity, volume record/surge, day/week streaks, 50/200-day SMA cross, biggest single-day move, NR7 (tight range), AVWAP hold/reclaim (`723`), and POC facts (`870`) — this is what constrains what copy may *say*, separate from and only loosely coupled to what the chart *draws* (e.g., MACD is never a "fact" here even though it's always drawn; RSI/Bollinger/Ichimoku facts don't exist because nothing computes them for this module).
