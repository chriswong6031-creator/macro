## Model routing (STANDING — token economy)

The main session may run a frontier model (Fable/Opus). **Never let fan-outs inherit it.** Workflow `agent()` calls and Agent-tool spawns inherit the session model unless you pass `model:` explicitly — under ultracode that silently burns frontier tokens on mechanical work. Route every spawn:

| Tier | Use for | Never for |
|---|---|---|
| **fable** (main loop + gated spawns/stages) | planning, adjudication, rulings, merges, final synthesis; taste-as-deliverable design (heroes, new visual language) via the gate below; spawns ONLY via `orchestrator` + FABLE-WHY; workflow stages ONLY with a script-level FABLE-WHY (see below) | bulk ×N mechanical fan-outs, ungated workflow stages, anything passing the draft-and-review test |
| **opus** | **building code/PRs/refactors/tests (via `builder`)**, reviews, judge/red-team critics, stats/math review, hard debugging, user-facing design/UI work (via `designer`) | bulk census, mechanical non-code sweeps |
| **sonnet** | census/exploration lanes, mechanical non-code fan-out, doc drafts | **building/writing shipping code (→ opus `builder`)**, final adjudication, user-facing design surfaces (route to `designer`) |
| **haiku** | trivial extraction/format sweeps | anything needing judgment |

Also set `effort: 'low'` on mechanical workflow stages; reserve high effort for verify/judge stages. Rule of thumb (operator 2026-07-21 — "no more sonnet building code"): **Opus builds, reviews, and designs; Sonnet handles mechanical non-code fan-out (census/exploration); Fable (main loop) plans/adjudicates/merges.**

**Design lane (operator order 2026-07-18 — "design sessions degraded"):** user-facing design/UI work is judgment work, never mechanical — do NOT route it to sonnet builders. Default home = `designer` (opus-pinned agent type; auto-loads the frontend-design skill + DESIGN_DOCTRINE.md). Taste-as-deliverable surfaces that fail the draft-and-review test (hero sections, new visual language, flagship page revamps) → do the design in the main loop, or spawn fable via the existing `orchestrator` gate with `FABLE-WHY: creative: <reason>`. The `builder` agent (now Opus-pinned, see Build lane below) may implement a *fully specified* design (exact markup/CSS handed to it) — the choice of palette, type, layout, and copy is what must stay with `designer`/Fable.

**Build lane (operator order 2026-07-21 — "sonnet design and building suck too much for our purposes"):** code implementation — writing code, PRs, refactors, tests — is now **Opus** work, not Sonnet. The `builder` agent type is Opus-pinned (spawns using it pass the guard without a `model:` param); Opus now builds **and** reviews. Sonnet's role narrows to mechanical **non-code** fan-out — census/exploration/lookup sweeps via `Explore`/`general-purpose` with explicit `model: 'sonnet'` — and Haiku to trivial extraction/search. A fully-specified design may be implemented by the Opus `builder`, but design *choices* stay with `designer`/Fable (Design lane above). Existing masterplans that say "Sonnet builds via `builder`" now route to Opus automatically — the agent type is unchanged, only its model tier moved up. (The autonomous metabolism build loop is likewise Opus-pinned as of 2026-07-21 — R-V4-2 amended, `scripts/metabolism_build.py`; its per-cycle budget cap is unchanged, so it may build fewer proposals per night at Opus rates.)

Legit = fails the **draft-and-review test** — Sonnet-draft + Opus/main-loop-review would NOT recover the quality: open-ended judgment steering major downstream work, long-horizon orchestration with irreversible mid-task decisions, or taste-as-deliverable creative work. Topic importance alone does NOT qualify (important-but-mechanical → sonnet; critique of an existing artifact → opus). Never fable ×N mechanical fan-outs. **Workflow stages may route to fable (operator re-enable 2026-07-18, "fable ultracode") ONLY when the script carries the same `FABLE-WHY: <category>: <specific reason>` line** — reserve fable stages for judge/synthesis work where the draft-and-review test fails; default synthesis home remains the main loop after the workflow returns. ## Spawn-handoff law (STANDING — quality does not travel by pointer; onboarding postmortem 2026-07-23)

A spawned/chipped session starts with ONLY its prompt + the target repo's CLAUDE/AGENTS file. The onboarding flow shipped broken-and-ugly despite a correct masterplan AND correct model tiers (Fable loop + Opus builders): reference shots existed only as prose, acceptance gates sat at §6/§7 of a referenced doc, the target repo's agent laws were 5 lines of Next.js warnings, and the PR self-merged with no visual artifact. Tiering is NOT the quality lever — binding context is. When commissioning build work (chips, handoffs, cross-repo especially):

1. **Acceptance gates INLINE in the spawn prompt**, phrased "not done unless": fresh end-to-end happy path with zero manual workarounds (a race you reload around is a bug you own); per-step visual crops vs the reference (light+dark+zh where applicable) posted in the PR body; entry points actually wired. A masterplan pointer is context, not enforcement.
2. **Reference images = committed files** (`mockups/refs/<program>/`) with paths in the prompt. Never hand off a look in prose — the session cannot see your screenshots.
3. **Design-spec-first**: flagship user-facing surfaces get exact markup/CSS pinned in the spawned session's main loop (frontend-design skill + target repo design docs) BEFORE builders assemble anything. "Component assembly" on unpinned design = house-idiom drift, even with Opus.
4. **No child-agent self-merge on first pass** of flagship UI — the spawned builder returns its PR + visual artifact to the commissioning main session. The main session reviews it and completes the normal squash-merge/live chain in the same task unless the operator explicitly requests a hold or a genuine check is red.
5. **Masterplans for user-facing builds carry ACCEPTANCE GATES as §0** at the top of the file, not buried mid-doc.
6. **Audit the target repo's CLAUDE/AGENTS file before spawning** — if it carries no design/verification laws, fix that first (charting-app `terminal/AGENTS.md` got its laws 2026-07-23).
7. **The build surface follows the FUNNEL, not the plumbing** — where the auth/billing machinery lives never decides where the user experience lives (onboarding sheet belonged to the landing, not the terminal app).
