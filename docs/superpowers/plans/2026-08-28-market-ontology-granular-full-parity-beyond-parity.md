# Market Ontology Granular Full-Parity + Beyond-Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the existing Market Ontology complete-parity program into a provably exhaustive row-traceable implementation program that reaches production functional parity and then runs a continuing beyond-parity synthesis ratchet.

**Architecture:** Preserve `WS:MARKET-OS`, `WS:ALPHA-INTELLIGENCE-INTEGRATION`, specialist canonical owners, F00 program control and F01-F13 lane identities. Add no new workstream/control plane. F00A admits exact retained evidence, F00B remains the live coarse 88+delta crosswalk, F00C performs granular 1,556+delta reconciliation, F01-F13 close implementation/proof gaps, and F00D converts parity-complete families into Mastermind-native expansion hypotheses.

**Tech Stack:** Markdown/CSV/JSON research artifacts, Agent OS records, GitHub PR/CI/fences, current Mastermind repository owners, Linear selective projection, Slack exact-thread transport/watchers.

**Spec:** `docs/superpowers/specs/2026-08-28-market-ontology-granular-full-parity-beyond-parity-design.md`

## Global Constraints

- Priority controls sequencing, never inclusion.
- Every admitted granular source row must remain traceable after family compression.
- No third MarketOntology workstream, lifecycle, queue, identity, truth store, graph, evaluation plane or watcher control plane.
- Original Mastermind code/design + lawful first-party/public/licensed data only; no competitor proprietary code, text, corpora, assets, branding, credentials or hidden/private interfaces.
- Product/research parity never grants rank/gate/size/origination/`ENTRY_OPEN`/Prophet/trade authority.
- F00B existing operation `marketontology-f00b-current-owner-crosswalk-20260828-sol-001` is not restarted or widened.
- F04 existing carriers remain separate and one-carrier-bound; this plan does not replace them.
- Manual Slack routing is avenue-first; Sol chooses `PREFERRED_AVENUE`, Chairman chooses the quota-bearing account/session unless explicitly delegated.
- Every watcher-enabled return receives one explicit same-carrier Sol continuation or terminal STOP.
- Every implementation child names the exact source rows/families it closes and requires real consumer/production proof before `PARITY_SATISFIED`.
