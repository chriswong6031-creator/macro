# TP-3 P0/P1 Estate Theme-Parity Census Execution Plan — V2

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to execute this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce an evidence-backed P0/P1 census of customer surfaces classified `GOOD`, `LIGHT_DEBT`, or `BROKEN`, grouped by the actual shared presentation owner so Sol can commission one bounded TP-4 family repair next.

**Architecture:** The canonical product page registry owns page identity/population. Existing page-evidence/light-sweep tooling owns captures. This dated research artifact records human/Opus visual adjudication and repair grouping only; no runtime/config consumer may treat it as another registry or score.

**Tech Stack:** `data/product_experience/page_registry.json`, `scripts/capture_page_evidence.py`, `scripts/light_mode_sweep.py`, Playwright/Chromium, Markdown research artifact.

**Spec:** `research/THEME_PARITY_RATCHET_PRESENTATION_CONVERGENCE_ARCHITECTURE.md`

**Prerequisites:** Canada TP-1 and HK TP-2 are production-accepted and their registry compliance closeouts are merged. Start from fresh `origin/main`.

## Global Constraints

- TP-3 changes no customer page, theme token, component, or runtime behavior.
- Every row keys to an existing canonical `page_id`; route/title similarity never creates identity.
- `GOOD`, `LIGHT_DEBT`, `BROKEN` are temporary census review classes, not product grades or machine authority.
- Automated smells never assign a class. Human/Opus inspection of dark/light evidence is mandatory.
- Capture/auth gaps remain explicit; an inaccessible state is not omitted or guessed.
- Canada/HK are reference examples of quality/process, not semantic templates for unrelated pages.

### Task 1: Freeze the exact P0/P1 population from the canonical registry

- [ ] Rebuild/validate the page registry using the command documented on fresh main in `config/product_experience/page_registry_overrides.yml`. Do not commit regenerated bytes if unchanged.

- [ ] Export the included rows deterministically:

```bash
python3 - <<'PY'
import json
from pathlib import Path
payload = json.loads(Path("data/product_experience/page_registry.json").read_text())
rows = [r for r in payload.get("pages", []) if r.get("priority") in {"P0", "P1"}]
for row in sorted(rows, key=lambda r: (r.get("priority", ""), r.get("page_id", ""))):
    design = row.get("design_system") or {}
    print("\t".join([
        str(row.get("page_id", "")),
        str(row.get("priority", "")),
        str(row.get("route_kind", "")),
        str(row.get("route", "")),
        str(row.get("archetype", "")),
        str(bool(design.get("compliant"))),
        str(row.get("source_template", "")),
    ]))
PY
```

- [ ] Create `research/THEME_PARITY_ESTATE_CENSUS_2026-09.md` with the exact fresh-main SHA computed by `git rev-parse origin/main`, and a Population table containing each canonical row. Do not hand-type a guessed SHA.
